fix(P129): UnboundLocalError in the P127 change, plus a static def-before-use gate

My bug, and it broke the first server run of the day (2026-10-02 13:59):

  UnboundLocalError: cannot access local variable 'lm'

In P127 I put `_tel._accel_device = getattr(lm.net.readout, ...)` 189 lines
BEFORE `lm = PHDWordLM(...)` - the Telemetry block sits at line 613, the LM is
created at line 802. py_compile cannot catch this (the name is perfectly legal
in the function's scope) and I did not run the entry point locally, so it only
exploded on the real production startup path.

Fixed by moving the assignment to immediately after the LM is constructed.
Also corrected the attribute name from `_device` to `device`, which is what
AccelReadout actually exposes.

New gate: an AST scan for "local variable used before it is assigned", added to
verify_ms_stream.py - which already carried the "run --help across every argparse
entry point" gate, so the philosophy matches. Threshold is 30 lines, since
ordering within a line or two is ordinary control flow. It walks every function
in train/train.py and train/infer.py.

The gate is verified to actually catch the bug: re-introducing the misordering
makes it FAIL and it names the variable and both line numbers
(`train/train.py:main() inside vocab_text assigned@L683 but first used@L614`);
restoring the file makes it PASS again. ms_stream goes 42 -> 43 cases.

Honest limitation of the new gate, recorded in the code: a static order check
can only catch cases inside the same function and more than 30 lines apart. A
definition in a different function, or a misordering only a few lines wide
inside a branch, slips through. So this does NOT replace the discipline of
running a smoke test locally whenever the startup path is touched - it just
catches the gross version of the mistake.

Gates: fast 9/9, ms_stream 43/43, accel_sparse 31/31, cann_env 26/26,
accel_readout PASS, and a local smoke run confirms zero UnboundLocalError /
Traceback markers.
