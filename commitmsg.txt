fix(P140): a typo crash, plus a static gate I had to withdraw after measuring it

The crash was mine: in the line profiler's diagnostic section I wrote
_ro._staged_to_dev(h) where the variable is ro, so the Ascend run died with
NameError. Fixed, two occurrences.

More interesting is the gate I tried to build to catch that class of error. I
wrote an AST scan for locals that are read but never assigned, expecting it to
be a cheap permanent guard. On this host it produced 15 false positives against
1 real finding: RESULTS is assigned at module level on line 35 of
audit_brain_parity.py, rows is a closure variable defined in main() and read by a
nested rec(), and train_tokens and resume are the same shape. Reliable
detection of undefined names needs a real symbol table such as pyflakes;
a few dozen lines of AST can only approximate it, and mine approximated badly.

So I withdrew the gate, and left a comment explaining why not to add it again.
A gate with a 15:1 false positive ratio is worse than no gate at all, because
people learn to ignore it. Reliability beats coverage for a check that is
supposed to be trusted.

The replacement is tools/smoke_benchmarks.sh, which short-runs five benchmark
tools. It has zero false positives and genuinely catches import-time explosions,
misspelled names and bad arguments. Verified: reintroducing the _ro typo makes
it report SKIP with exit code 1 (correctly classified as an NPU-environment
failure while still detecting the error), and restoring the file returns it to
all green.

The smoke script had a blind spot of its own, now fixed. The diagnostic section
began with `if not _use_pin: break`, and this host always takes the numba
fallback, which has no _pin_bufs - so the whole section was skipped, and a typo
inside it went undetected even with the smoke script in place. I confirmed that
empirically before changing it. It now runs regardless of whether pinned memory
is available: the fallback measures the upload cost itself, the accelerated path
measures the pinned pool rotation wait. The general lesson: every early-return
or guard in a gate is a blind spot, and the question to ask is which branch the
default local configuration actually takes.

I also tripped over this file's check() signature once more - it is check(name,
cond) with two arguments and no detail, unlike most verifiers which take
(cond, name, detail) in the opposite order. There is now a prominent comment and
a _CHECK_ARITY constant at the top of verify_ms_stream.py.

Gates: fast 9/9, ms_stream 44/44, smoke_benchmarks all five OK.
