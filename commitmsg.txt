fix(P133): the segment benchmark measured the wrong model; source it from the production ckpt

Server run 2026-10-02 14:48 crashed, and the output shows why the whole run was
meaningless before it even started:

  [bench] backend accel:auto | n_out=1,021 n_h=3,072 conn_k=0 dtype=fp32

n_out should be 51,962, and conn_k should be 128, not 0. The tool read the
vocabulary snapshot, then fed PHDWordLM a 4000-character slice of it - which
re-tokenized into a 1,021-word vocabulary. Every number that run could have
produced would have described a different model.

Fixed properly rather than patched: the tool now sources everything from a
production checkpoint, which already carries the real structure -
tok_vocab for n_out, ro_ip/ro_idx for conn_k and the n_h bound, plus the stack
weights. Added --ckpt to point at a specific file; by default it picks
outputs/models/*1b*pretrain*.npz. When conn_k comes out as 0 the tool says so
loudly, because that is the signature of "you are not measuring the production
path".

Also fixed a genuine trap in my own code: getattr(ro, "_csr", None) does NOT
return None when the readout is dense - `_csr` is a property that RAISES
NotImplementedError, getattr's default does not suppress exceptions. That was
the traceback. Wrapped in try/except, and noted in the comment so it is not
rediscovered.

One more robustness fix: the n_h back-inference from ro_idx only holds when the
CSR row count equals n_out. When it does not (the local smoke ckpt has 637
vocab words against 2611 CSR rows), n_h stayed None and then blew up when used
to build the test vector. It now always resolves to an integer and prints the
value for the operator to check.

Verified locally end to end (the local ckpt is a small dense one, so the
numbers are reference-only, but both the sparse and dense paths execute without
error). fast 9/9, --help exit 0.

Please rerun on Ascend with

  python tools/bench_readout_segments.py --preset 1b

The line that matters is "[bench] sparse CSR: rows=... conn_k=... nnz=..." - if
it does not appear, the ckpt is not the production pre-training one and the
measurements will not transfer.
