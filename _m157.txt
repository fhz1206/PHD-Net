fix(P157): restore the --readout-int8-compute flag that P153 lost

While preparing the server test checklist I noticed that --readout-int8-compute
was missing from --help and argparse rejected it outright, even though
cfg.readout_int8_compute was being read in the body of the file. Without this the
whole P154 to P156 chain is unreachable from the command line, so no A/B run
against the 910B would have been possible.

The cause was my own P153 edit: the bash heredoc that inserted the argument ate
its quoted strings and a later restore replaced the file from git, dropping the
block while leaving the line that consumes it. I verified the absence before
fixing it by checking --help, grepping for the argument, and confirming argparse
rejected it with "unrecognized arguments", then confirmed the fix by checking
that --help now lists it twice, once as an option and once in its help text, and
that the module still compiles and --help exits zero.

Nothing about the default changed. It is auto, which means fp8 storage with int8
compute, as fhz specified.

The lesson worth recording is that argparse can silently accept a missing
consumer: the code path that reads a config field will raise AttributeError only
if the config lacks the attribute, so a flag that never existed is invisible until
someone runs the command. The checklist for the 910B should include a first step
that asserts every planned flag appears in --help.
