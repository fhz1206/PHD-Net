## 2. 四条铁律（不可违反）

1. **禁止自注意力 / 位置编码 / 堆叠层**。
2. **每个机制必须有神经认知对应物**（M1–M6 各自对应一处解剖学/神经生理结构）。
3. **逐 token 语义，禁止批处理**。状态跨 token / shard / epoch 连续。
4. **行为变更用 config 开关承载，默认关闭**（例外：稀疏模式 default-on，是项目特例）。

## 4. 精度现状

### 4.1 保留率实测（`[工具]` probe_readout_precision.py，`|W|~1e-2`、`|dp|~1e-6` 档）

| 精度 | 非目标行更新保留率 | 含义 |
|---|---|---|
| fp32 | 99.95% | 学习规则基本完整 |
| fp16 | **26.67%** | 学习规则**部分退化为纯 Hebbian** |
| bf16 | **5.79%** | 几乎纯 Hebbian |

**⚠ 这是默认档的代价**：默认 fp8（P189）意味着**默认就在承担比 fp16 更粗的量化步长**（fp8 步长比 fp16 粗约 4 倍，非目标行保留率低于 fp16 的 26.67%）。这不是缺陷，是 fhz 2026-10-07 的决策（P189「模型 fp8，迭代 fp16」）；fp16 保留率数字仍有效作对照（P110 实测口径）。

**⚠ 判据陷阱（务必读）**：基线必须经过**同一精度舍入**。拿 fp32 值与 fp16 值直接比，会得到「fp16 保留 100%」的**反向假阳性**。

### 4.2 当前支持的精度（P189，fhz 2026-10-07）

| 可用 | 说明 |
|---|---|
| **`fp8`（默认）** | fp8 e4m3fn **位模式（uint8 承载）存储** + fp16 迭代计算；910B 无 fp8 算子 → 每步 CPU 转换 int8 计算可选（`--fp8-conv`） |
| `fp16` / `bf16` / `fp32` | 显式可选；fp16/bf16 请求运行时提升 fp32（P187） |
| 降级链 | fp8 → fp16 → bf16 → fp32（探测「真跑一次」决定） |

| 已禁用 | 原因 |
|---|---|
| `int8` / `int16` / `int32` 显式请求 | P163（int8 累加数学上不可能：127×127 > 127）；fp8 降级路径自动用 int8 **算子**不受此限 |
| `fp4` / `int4` | unpack 开销抵消存储收益（P152） |

**int 的一条硬约束（P156，数学事实）**：`127 × 127 = 16129` > int8 上限 127 → **单个乘积就溢出 126 倍**，累加更甚。所以社区的 int8 GEMM 一律是「**int8 输入 × int32 累加器**」，这不是妥协是定义。

### 4.3 fp8 的放行口径（P189 覆盖 P167）

P163/P167 曾把 fp8 静态剔除或交给 `PHD_FP8` 开关 —— P189 起**显式请求 fp8 一律进候选链首**，由运行时探测「真跑一次」决定：有原生 fp8 算子直接用；910B 上探测失败 → **fp8 位模式（uint8 承载）存储**，访存与原生 fp8 相同（1 B/元素）。**int 族显式请求仍是硬禁用。**

### 5.1 四档预设

| 预设 | width | conn_k | big_ltm_N | big_ltm_m | 容量 |
|---|---|---|---|---|---|
| `smoke` | 256 | 32 | 2^20 | 60 | ~6.3e7 |

| `1b_max` | 4096 | 512 | 2^24 | 60 | ~1.0e9 |
| `30b` | 1024 | 128 | **2^29** | 56 | **30.295e9** |

⚠ `big_m` 72→56 是**显式取舍**（控总容量），代价是**每神经元出边上限 −22%**。

### 5.2 30b 档的内存真相（P166修正）

**旧文档说「需≥ 200 GB」，那个数字对不上任何实际占用。** 真实情况：

| 项 | 旧（稠密索引） | 现（P166 哈希表） |
|---|---|---|
| 反投影索引 `rev_indptr` | **4094 MB** | **256 KB** |
| 键数 | — | 4096（= `n_dim × k_hash`，与 `n_neurons` 无关） |

依据：`rev` 的真实键数只有 `n_dim × k_hash = 4096` 个，而稠密 `indptr` 按 `max(big_i)+1 = 2^29` 铺开 → 99.98% 是空区间。

## 7. 平台差异铁律（写性能文档必标）

**x86 的性能数字不构成昇腾/ROCm 的证据。** 已实测**七次里五次方向相反**：

| 项 | x86 | 昇腾 |
|---|---|---|
| M1 fp32 GEMV | 快 1.80× | **慢 ~70×** |
| M2 融合核 | 快 1.15–2.16× | **慢 8–13×** |
| `OMP_PLACES=cores` | 无感 | **慢 8×** |
| `--m2-kernel` | `fused` 更快 | `plain` 快 **5.41×** |

**唯一两条跨平台都成立的规则**：
1. 性能数字必须带平台 + 档位，且注明「未在目标平台实测」。
2. 判据= **真跑一次**，不是查表、不是硬编码禁令。

| 项 | 状态 | 依据 |

| `TORCH_BLAS_PREFER_HIPBLASLT=1` | **默认开** | ROCm 官方 env 参考：让 GEMM 优先走 hipBLASLt |
