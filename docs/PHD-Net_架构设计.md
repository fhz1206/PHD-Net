## 0. 设计动机

Transformer 把「关联」建模为**全局成对相似度**（QK^T，O(T²·d)），把「记忆」建模为**无学习的
KV 缓存**，把「学习」寄托于**非局部的反向传播**。这三点都与人脑的工作方式相去甚远：

| 人脑做法 | Transformer 做法 | PHD-Net 的选择 |
|---|---|---|
| 突触局部可塑性，无需全局梯度 | 反向传播（全局、非局部） | 全部学习规则**局部化**（每个突触只看自己两端） |
| 稀疏放电（~1–5% 神经元活跃） | 稠密激活 | **k-WTA 稀疏编码**（SDR，稀疏分布式表示） |
| 海马快印迹 + 皮层慢巩固（双系统） | 单一权重 + KV cache | **双速率记忆**：快权重（海马）+ 慢权重（皮层） |
| 前额叶有限容量工作记忆 | 上下文窗口随 T 线性/平方膨胀 | **有界槽位工作记忆** + 长期记忆检索 |
| 层级预测：高层级预测低层级输入 | 无生成式层级 | **预测编码层级**（自由能最小化） |
| 神经调制（DA/NE/ACh）门控学习 | 固定学习率 | **全局调制标量**门控学习率与编码/检索模式 |
| 连接率 ~2e-8、单神经元约 1744 条突触 | 稠密全连接 | **结构性稀疏连接**（不存在的突触不存储、不计算） |

四条总原则：

1. **无自注意力**：任何位置都不出现 QKV 投影与全局成对相似度计算；时序关联由**突触迹
   （STDP）**与**状态迹**承载，计算量与活跃神经元数成正比，而非与历史长度平方成正比。
2. **学习规则局部化**：每个突触的更新只依赖其前/后端神经元活性、局部迹、及一个全局标量
   调制信号——无反向传播。
3. **稀疏即效率**：全网络采用稀疏分布式码（SDR）与稀疏连接；激活与存储只触碰活跃通路。
   **稀疏性是架构原则，不是优化手段**——逐项账见 §3。
4. **双速率记忆**：一次性经验写入快权重（海马式印迹），统计规律缓慢巩固入慢权重（皮层式学习）。

## 1. 四条铁律

这四条是硬约束，违反即不是 PHD-Net。**任何新增行为都要同时满足它们。**

### 铁律一：禁自注意力、禁位置编码、禁堆叠层

- **不出现** QKV 投影、`softmax(QK^T/√d)V`、因果掩码注意力；
- **不注入位置**——「第 k 个位置」不存在于任何向量中，时间信息由 STDP 因果链与情景缓冲的
  链式回放承载（顺序即连接）；
- **不堆叠同构层**——抽象由预测编码层级（生成-识别闭环）与分层摘要实现，每层是独立
  脑区式模块，有自己的记忆与调制，而非同一残差流的重复块；
- 代价：失去「任意两 token 一步直达」，长程关联依赖 WM 槽位与 LTM 检索的**间接通路**，
  计算量从 O(T²·d) 降到 O(活跃 × m)。

### 铁律二：每个机制必须有明确的神经认知对应

不允许「工程上方便」的机制进主干。不接受的例子：为了并行度而加的注意力近似、为提升指标
而加的无脑正则。新机制的准入条件是：能说清它对应哪个真实神经现象、为什么这个现象需要它。

### 铁律三：逐 token 语义 → 不允许批处理

网络是**逐 token 状态机**：状态（WM 内容、LTM 突触、STDP 迹与时间戳、调制器统计量）
跨 token / 跨 shard / 跨 epoch **连续演化**，读出权重 W 每步原地更新。因此：

- **不允许 batch 维**——batch 化会破坏「每个样本都写同一份记忆」这一记忆语义，
  等价于把记忆变成 minibatch 梯度；
- 由此推出：读出侧唯一允许的「批量」是 `minibatch_size > 1` 的**梯度累积**（先累积 N 步
  梯度再平均更新一次），它不改变逐 token 前向与状态演化；
- 并行只能来自**部件内/层内的稀疏结构**（CSR 按行、numba `prange`），不来自样本维。

### 铁律四：行为变更以 config 开关承载，且默认关闭

新增机制必须是一个默认 `False`（或默认等价旧值）的 config 字段，使**默认路径逐位不变**。
这样才能把「机制是否贡献」与「机制是否存在」分成两个可独立回答的问题。

**两个例外（default-on）**：

| 开关 | 为什么例外 |
|---|---|
| `sparse_conn` | 2026-09-28 按指令**删除稠密 PC 栈**，主干唯一实现就是 CSR 稀疏图；传 `False` 在 config 校验期 fail-fast |
| `k_sparse` | 2026-09-24 起默认 16（原 32），「稀疏要默认开启」；评测脚本显式传自己的值，故既有评测口径不受影响 |

## 2. 数据流与状态演化

### 2.1 端到端数据流

```
文本
  │ ① 分词：CSR-trie + 最长匹配贪心（numba njit(nogil) 核，多线程）
  │   自适应查找结构：边数 ≤2 万走 CSR 二分，>2 万走边哈希（Knuth 乘法混合）
  ▼
token id
  │ ② SDR 复合编码：[当前词 SDR ; 前一词 SDR]（T2.3 上下文绑定，前词 OOV 时安全退化）
  ▼
x_t  ──▶ M1 k-WTA 稀疏编码（输出 12.5% 稀疏）──▶ s_t
                                                    │
                              ┌─────────────────────┴──────────────────────┐
                              ▼                                            │
                    M2 预测编码层级（CSR，conn_k=128 → 12.5% 连接率）      │
                       上行：识别 r_{l+1}                                   │
                       下行：生成 ŷ_l；误差 e_l = s_l − ŷ_l                  │
                       推理时 n_infer_steps 步误差驱动精炼                   │
                              │ 顶层表示 r_top + 底层误差 e0                   │
              ┌───────────────┼────────────────┬──────────────┐            │
              ▼               ▼                ▼              ▼            │
        M3 STDP 时序    M5 调制（‖e0‖→z）   M4a WM       M4b 长期记忆      │
        p_t = f(W·rate)   gate / 模式      漏衰减+门控写入  印迹 / 吸引子检索 │
        (因果时序预测)    (全局标量广播)    (漏整合+摘要槽)  (事件驱动 2²⁴×72)  │
              │               │                │              │            │
              └───────────────┴────────┬───────┴──────────────┘            │
                                       ▼                                   │
                          h = [r_top ; WM ; 预测特征]（pred_in_readout 三拼）│
                                       ▼                                   │
                            M6 读出：y = softmax(W_ro · h)                  │
                                       ▼                                   │
              Hebbian / 局部规则更新（误差×上层表示、Oja、STDP 迹、印迹）◀───┘
```

### 2.2 五条通路

- **前馈流**：x → SDR 稀疏码 → 逐层自下而上识别 → 顶层表示；
- **反馈流**：高层级向低层级发送预测，低层级只上传**预测误差**（预测编码核心）；
- **横向流**：层内 Hebbian/Oja 关联（特征绑定），跨时间步 STDP 因果绑定（序列结构）；
- **记忆流**：工作记忆 ⟷ 长期记忆（写 = 印迹；读 = 吸引子模式补全）；
- **调制流**：底层预测误差范数 → 意外度（surprise）→ 门控所有模块的学习率与工作模式。

### 2.3 状态连续演化（铁律三的直接后果）

- 训练循环保证 WM / STDP / LTM 状态**全程不重置**：跨样本、跨分片、跨 epoch 连续；
- 「context」在本项目里**不是窗口长度**，而是记忆机制的有效范围——没有 `max_len` 这类
  硬截断参数，训练数据无论多长都不截断（字符级流式，内存与语料总长无关）；
- 推论：评估必须用 `readonly=True` 路径冻结全部持久状态，否则重复评估会得到不一致的结果；
- 检查点保存完整运行时状态（STDP 迹 / 调制器统计量 / step_count 等），`--resume` 快进至断点。

### 2.4 单个时间步的推理与学习顺序

```
1. M1  s_t = kWTA(W_enc · x_t)                    # 稀疏编码
2. M2  自下而上生成 r1、r_top；自上而下算误差 e0、e1
         并做 n_infer_steps 步误差驱动精炼（自由能下降）
3. M3  p_t = f(W_seq · rate(r_top_{t-1}))         # 时序预测
         seq_err = 1 − cos(p_t, rate(r_top_t))
4. M5  surprise = ‖e0‖ → z 标准化 → gate、模式（编码/检索）
5. M4a WM 衰减（摘要槽免衰减）；若 gate > 阈值则写入槽位
6. M4b 若编码模式 → 事件驱动印迹
         若检索模式 → 由 WM/r_top 线索做吸引子检索 → 回填 WM
7. M6  y_t = softmax(W_ro · [r_top ; WM ; 预测特征])
8. 学习（若开启）：所有突触按 §4 局部规则 × gate 同步更新
```

**训练即推理**：在线、单样本、无 epoch 概念。周期性调用 `sleep()`——巩固快权重入慢权重、
衰减过时印迹（离线回放的抽象）。

## 3. 稀疏性账（架构原则，不是优化手段）

### 3.1 人脑参照

- 皮层单个锥体神经元约 **10³–10⁴** 条突触，潜在靶点 ~10¹¹ → **连接率 ~2e-8**（长程）到
  10% 量级（局部）；
- 平均每神经元约 **1744** 条突触；
- 任一时刻约 **1–5%** 神经元活跃。

### 3.2 本项目逐项对照

| 部件 | 当前稀疏性 | 脑对应 | 状态 |
|---|---|---|---|
| M1 编码输出 | **k-WTA 稀疏**，输出 **12.5%** 活跃 | 皮层稀疏发放 + 侧抑制 WTA | ✅ 成立 |
| M2 预测编码主干 | **CSR 结构性稀疏**，`conn_k=128` / `n_in=1024` → **12.5% 连接率** | dense representation + sparse connectivity | ✅ 成立 |
| M3 STDP 时序核 | 每神经元 `m_lateral=16` 出边 → **1.56%** 连接率（16/1024） | 稀疏拓扑突触迹 | ✅ 成立 |
| M4a 工作记忆 | **4 槽位**硬上限（+1 摘要槽免衰减） | dlPFC 有限容量 | ✅ 成立（有界） |
| M4b 大容量表 | **事件驱动**：只触碰已生长条目，每神经元 ≤`m` 条出边为硬容量约束 | 海马稀疏索引 | ✅ 成立 |
| M5 神经调制 | **单标量 / 四通道全局广播**，零参数 | 弥散投射 | ✅ 成立（无突触） |
| **M6 读出** | **100% 稠密**（`readout_conn_k=0`） | 人脑连接率 **2e-8**、每神经元约 **1744** 条突触 | ❌ **明确的架构欠账** |

**关键区分**：「稠密矩阵 + 稀疏更新」≠「结构性稀疏连接」。M2 属于后者——**不存在的突触
不存储、不计算**（CSR 只承载 `n_out × conn_k` 条存在的边），这才是与人脑同构的那一种。

### 3.3 M6 读出欠账（必须直说）

**M6 读出目前 100% 稠密，这是一个明确的架构欠账**，不是实现选择：

- **同构债**：与人脑 2e-8 连接率差 4 个数量级；读出是全项目唯一没有稀疏化的部件；
- **性能债**：读出权重是全项目最大的一块访存（口径见性能文档）；
- **技术债的性质**：稀疏读出的朴素版本（每输出单元 k 条入边）**已经存在**
  （`readout_conn_k`，CSR 承载）但**未启用为默认**——因为实测是「吞吐换精度」，
  在当前评测口径下不划算；这属于**配方选择**，不能替代架构上的稀疏化。
- **已设计未实施**：**幂律稀疏化方案**——把读出按幂律分布稀疏到 5–12% 活跃度，
  方案已设计、尚未实施。它同时是同构与性能的双重收益点。

结论：M6 的幂律稀疏化是当前**最高优先级的架构开放项**（编号见路线图文档的开放项表）。
在它落地之前，任何关于「本架构稀疏度已达标」的说法都不成立。

### 3.4 1B 档容量账

1B 档的「1B」= **总突触参数容量 ≥ 1.0×10⁹**（容量上限口径，不是已用量）。构成：

| 组成 | 机制 | 规模（`--preset 1b`，width=1024） | 占比 |
|---|---|---|---|
| **M4b 大空间事件驱动表** | 2²⁴ 神经元 × 72 出边上限 = **1.208e9** | 主体，随经验生长 | **≈ 88%** |
| M6 读出（稠密） | 词表 × `n_h`（3 拼 = 3×1024） | 稠密 | **≈ 11.6%** |
| M1 编码器（稠密） | 组合输入 2048 → 1024 + 偏置 | 稠密 | **≈ 0.16%** |
| M2 主干 CSR | 4 层 × 1024 × 128 | 12.5% 连接率 | 计入稀疏侧 |
| M3 STDP 侧向核 | 1024 × 16 | 1.56% 连接率 | 计入稀疏侧 |

**总容量 ≈ 1.317e9**（`train_1b/config_1b.py::capacity_report()` 的算术口径，启动时打印）。

读这张表的三个要点：

1. **稀疏侧占绝对多数（≈88%）**——这是「稀疏即效率」在容量层面的兑现；
2. **稠密读出占 11.6%**——它是 M6 欠账在容量账上的直接体现，也是读出成为访存瓶颈的结构原因；
3. **M4b 的 1.208e9 是容量上限而不是已用量**：突触不是构建即存在，而是随经验**生长**
   （结构可塑性，"fire together, wire together"）。`count_params` 计的是**已生长突触数**，
   训练初期利用率低，随经验趋近上限。日志会打印实时利用率，**不做虚标**；
4. **每步计算量只正比于活跃神经元数**（事件驱动），与 1B 总容量无关——这是容量与算力
   解耦的关键，也是「大容量」在本架构下可负担的原因。

## 4. 六机制与学习规则

### 4.1 M1 稀疏分布式编码器 SparseEncoder

- **神经认知依据**：初级感觉皮层的稀疏放电；抑制性中间神经元（SST/PV）介导的**侧抑制**
  与胜者全取（WTA）竞争。
- **机制作用**：把输入投影到高维空间后只保留 top-k 胜者，得到稀疏分布式表示（SDR）。
  SDR 的性质是「相似输入 → 重叠支撑集」，这正是稀疏分布式编码承载泛化的方式。
- **稀疏性**：输出 12.5% 活跃（`k_sparse` = n_sdr/8；库默认 16/256 = 6.25%，1B 档按档位放大）。
- **当前实现要点**：
  - `u = W_enc·x + b` → 半波整流 → k-WTA（`argpartition` 取 top-k）→ 归一化；
  - 复合编码（`encode_composite`）：拼接 `[当前词 SDR ; 前一词 SDR]` 作为 M1 输入，
    前词 OOV 时按「无前词上下文」安全退化；
  - `k_sparse > n_sdr` 在 config 校验期 fail-fast（否则 `argpartition` 的 kth 越界，
    构造成功但首个 step 才崩）；
  - 权重初始化支持皮层式 `lognormal_init`（重尾 + E/I 符号，默认关）；
  - 计算：迭代量全程 fp32（top-k 归一化与学习增量不在低精度下做），模型权重按
    `encoder_dtype` 存储。

### 4.2 M2 预测编码层级 SparsePCStack

- **神经认知依据**：皮层层级 V1→V2→V4→IT 的**预测编码**（Rao & Ballard 1999；
  Friston 自由能原理）；深层锥体细胞携带内容表示，浅层颗粒细胞携带误差信号。
- **机制作用**：高层级向下层发**生成式预测**，低层级只上传**预测误差**；误差自下而上
  逐层上传、预测自上而下逐层下发，构成闭环。顶层表示是当前内容的抽象。推理时做
  `n_infer_steps` 步误差驱动精炼，近似自由能最小化。
- **稀疏性**：`conn_k=128` / `n_in=1024` = **12.5% 连接率**，CSR 承载。**不存在的突触不
  存储、不计算**——前向与学习都只遍历存在的边，O(k·n) 而非 O(n²)。
- **当前实现要点**：
  - 结构：每层有识别（上行）权重与生成（下行）权重，四层往返（`n_sdr ↔ n_mid ↔ n_top ↔
    n_mid ↔ n_sdr`）；上行 `r_{l+1} = φ(W_up,l · e_l)`，下行 `ŷ_l = W_dn,l · r_{l+1}`，
    `e_l = s_l − ŷ_l`；顶层表示 `r_top`；
  - **稠密栈已删除**（2026-09-28 指令）：`sparse_conn=False` 在 config 层 fail-fast，
    主干唯一实现是 CSR 稀疏图；
  - `k = n_in`（全连接图）时与稠密语义一致；CSR 求和按列索引升序，与 BLAS 内部求和顺序
    不保证逐位相同，验收判据是容差对拍而非逐位；
  - CSR 矩阵-向量乘、稀疏外积累加、稀疏 Oja、裁剪都是 numba `prange` 按行并行核；
  - 融合核（`pc_fused_kernel`，默认开）把一次学习里的多次核调用融成一次，逐位等价；
    **平台差异铁律**：该融合核在 x86 快 1.15–2.16×、在昇腾 aarch64 慢 8–13×——
    **x86 的性能结论不构成证据**（详见规范 §4）；
  - 权重截断 `pc_w_max=2.0`（显式字段，避免历史上因签名默认值而静默生效）。

### 4.3 M3 STDP 时序预测 STDPCore

- **神经认知依据**：海马 CA3 递归可塑性网络；皮层局部突触的**脉冲时序依赖可塑性**
  （STDP，Bi & Poo 1998）——先发放的突触前神经元增强后发放的突触后连接，是**因果学习**。
- **机制作用**：用稀疏固定拓扑 + 突触迹模型实现时序预测：上一步的发放率经稀疏拓扑
  产生本步预测 `p_t`，预测与当前表示的偏差（`seq_err = 1 − cos(p_t, rate(r_top_t))`）
  就是**时序意外度**，同时供 `pred_in_readout` 的预测特征使用。
- **稀疏性**：每神经元 `m_lateral=16` 条出边 → 1B 档 **1.56% 连接率**；存储与计算只触碰
  活跃通路。
- **当前实现要点**：
  - 迹模型：`P_pre ← λ·P_pre + rate(r_{t-1})`，`P_post ← λ·P_post + rate(r_t)`，
    `Δw = η·(P_pre·post − P_post·pre)₊`，截断于 `[0, w_max]`。直觉：
    **「先响后响 → 增强；后响先响 → 抑制」**——网络自发学到时间因果结构；
  - 三条工程约束（源自生物学要点）：① 前/后迹的惰性衰减时间戳必须**独立**；
    ② 迹更新与学习的时间顺序决定 LTP/LTD 是否相消；③ 发放率输入**必须稀疏化**
    （稠密输入会使历史迹残留污染因果学习）；
  - numba 核（`_predict_edges` / `_stdp_delta`）带**运行时行为自检**（三重门槛：
    scatter 语义 + 一致缩放下权重增长 + numba/numpy 逐位等价）。不自检就退回纯 numpy，
    **行为完全一致**——教训是不能只判「权重有没有增长」，错误缩放会让两条路径同时失败；
  - **只走 numpy(+numba) CPU**：旧 torch 后端已随整体删除。STDP 的逐突触状态（自适应 LR /
    稳态 / 元可塑性 / E-I 分型）在 torch 上无法保留，迁移会丢机制；
  - 可选机制（默认关）：逐突触自适应学习率、多尺度双迹、稳态突触缩放（出行权范数超阈
    拉回，防发散）、BCM 元可塑性滑动阈值、E/I 突触类型（抑制性出边权重为负）。

### 4.4 M4a 工作记忆 WorkingMemory

- **神经认知依据**：背外侧前额叶（dlPFC）的**持续放电**（delay activity）与**漏整合**；
  基底核-丘脑回路的**门控**写入；前额叶对重要内容的**免衰减主动维持**（rehearsal）。
- **机制作用**：有界槽位工作记忆 + 调制门控——提供短程上下文线索，并向 LTM 检索与读出
  提供 cue。**有界**是架构要求：代价恒定，不随上下文长度膨胀。
- **稀疏性**：4 槽位硬上限（默认），+1 个**摘要槽**（免衰减、参与读出但不被覆盖）。
  容量本身就是稀疏约束。
- **当前实现要点**：
  - 每步全部普通槽位衰减 `×gamma_wm`（模拟持续放电的漏积分）；**摘要槽不参与衰减**；
  - 写入由调制门控决定——只有「意外」的信息才占用槽位（基底核门控假说）；
  - 读出为强度加权的槽位总和；`wm_content_address` 可按余弦相似度写入最相似的槽位
    （相似内容聚合，减少同义槽位碎片化；默认关）；
  - **摘要槽必须是「最弱槽位」选择的排除项**：否则长跑衰减后所有槽强度都 ≥1.0，
    argmin 会命中摘要槽，把受保护的重要内容覆盖成无关输入，长期污染读出；
  - 压缩摘要（`wm_summary_every=N`）把当前槽位加权内容经吸引子收敛为稳定表示存入摘要槽；
    大容量表路径下会先稀疏化为 top-1/8 幅值率再摘要（否则强成分主导）。

### 4.5 M4b 大容量事件驱动稀疏表 SparseLTM

- **神经认知依据**：**海马**（快速一次性印迹，索引理论）+ **新皮层**（慢速统计学习）；
  互补学习系统理论 CLS（McClelland, McNaughton & O'Reilly 1995）；海马 CA3 的自动联想；
  齿状回模式分离；TCM/CMR 时间上下文模型（Howard & Kahana 2002；Polyn et al. 2009）。
- **机制作用**：承接超出工作记忆容量的长程依赖。n_dim 维表示经确定性哈希派生
  `k_hash` 个大空间神经元索引（分布式编码，SDR 扩展），共激活的神经元之间**生长新突触**
  （结构可塑性）；检索由线索收敛到记忆表示。另有 `LongTermMemory`（快/慢权重 +
  吸引子检索 + 睡眠巩固）用于小规模非容量路径。
- **稀疏性**：**事件驱动**——只触碰已生长条目，未触碰不存储、不计算。1B 档容量
  **2²⁴ × 72 ≈ 1.208e9** 突触（每神经元 ≤72 条出边为硬容量约束）。存储有两种在线形态，
  **逐位等价**（`tests/verifiers/verify_csr_equiv.py`）：dict 邻接表（调试/短跑）与
  **在线可写 CSR**（`csr_online`，定长行 + 预留槽，1B 档默认开）。
- **当前实现要点**：
  - 印迹/召回在 numba 核里做；反投影索引 `rev`（大空间索引 → 绑定的表示维度）是
    **静态**的，一次构建后预 CSR 化供核使用，维度序与 dict 版一致以保证逐位相同；
  - 确定性哈希（不用 Python `hash()`，它进程间随机化会导致不可复现）；
  - 可选机制（默认关）：拓扑生长引导（偏好低入度目标，避免 hub 过载）、int8 值量化存储、
    分片 mmap 落盘、稀疏 Top-k 误差反传；
  - **规模诚实的边界**：「2²⁴×72」是容量上限，不是已用量，也不是已验证的算力吞吐——
    每步计算量正比于活跃神经元数，与总容量无关。

### 4.6 M5 神经调制 Neuromodulator / MultiModulator

- **神经认知依据**：蓝斑去甲肾上腺素（NE）/**意外**信号、腹侧被盖多巴胺（DA）的奖赏与
  巩固信号、基底前脑胆碱能（ACh）在「编码模式 / 检索模式」间的切换（Hasselmo）、
  5-HT 的耐心与冲动抑制。
- **机制作用**：把「意外度」变成全局调制标量，广播至 M2/M3/M4b，缩放各自学习率并
  切换工作模式。默认实现是单标量：底层预测误差范数 `‖e0‖` 经在线 Welford 标准化为
  z 分数，`gate = σ(a·z)`——**意外大 → 可塑性开大**（「先见者学，重复者忘」）；
  z 高 → 编码模式（印迹 + WM 写入），z 低 → 检索模式（吸引子提取）。
- **稀疏性**：**零突触、零参数**的全局标量广播（`multi_modulation` 开启时是 4 个标量），
  是稀疏性的中性项。
- **当前实现要点**：
  - 四通道版本（`multi_modulation`，默认关）把单标量细化为 ACh（编码/检索门控）、
    NE（新颖性 → 可塑性增益）、DA（巩固信号 → 海马/皮层巩固与回放强度）、5-HT（耐心 →
    检索等待节奏）；返回接口与单标量版兼容；
  - 另有滞后一步的**任务误差调制器**（`task_modulation`，默认关）：读出 NLL 的 z 分数
    门控 PC/STDP 学习率，**默认路径不参与**；
  - 审计发现：`ltm_imprint_gate` 默认 0.8 与调制器 z 分布（std≈0.32）叠加后，
    `gate > 0.8` 仅约 0.4% 的步触发 → 大容量表在 LM 训练中几乎从不印迹。默认值已下调以激活，
    这是**机制可达性**问题而非稀疏性问题，记录在此以免再次误判「机制无效」。

### 4.7 M6 读出头 Readout

- **神经认知依据**：IT → 前额叶 / 前运动皮层的决策读出；皮层→输出的投射是**多级中继 +
  群体编码**，而非单层线性分类器。
- **机制作用**：把顶层表示、工作记忆内容与时序预测特征拼成读出向量
  `h = [r_top ; WM ; pred]`（`pred_in_readout` 三拼），经 softmax 感知器输出词表分布。
  监督信号**仅存在于最末端**，主干完全无监督。
- **稀疏性**：❌ **100% 稠密（架构欠账）**。`readout_conn_k>0` 提供 CSR 稀疏路径
  （每输出单元 k 条入边，学习规则不变、仅连接存在性改变），但**未启用为默认**：
  实测是吞吐换精度。幂律稀疏化方案**已设计、未实施**（见 §3.3）。
- **当前实现要点**：
  - 两套局部学习规则：softmax 感知器 `ΔW = −η·(p − t) ⊗ h`（交叉熵梯度，只作用于末端），
    与非 softmax 感知器 `ΔW = η·(t − y) ⊗ h`（`readout_softmax=False`）；
  - **非 softmax 路径的历史符号修正**：曾写成 `W − η·outer(t − y, h)`，与融合核的
    `W += η·(t − y)⊗h` **符号相反**，只在融合核不可用时暴露，会朝错误方向学。当前
    两条路径符号已对齐；
  - 两级群体读出（`readout_hidden>0`，默认关）：h → 隐藏群体（稀疏投射 + k-WTA 竞争 +
    **局部无监督 Oja**）→ 输出（稀疏投射 + 任务监督），实现「误差只到第二级、不反传主干」；
  - 发育/退火/回放：`pc_dev_steps`（发育期后冻结表征）、`eta_readout_anneal` +
    `eta_readout_floor`（学习率乘性退火与下限，防后期样本覆盖早期学习）、
    `readout_replay`（旧 (输入,目标) 储备库在**当前表征**下只读前向并重训读出，
    缓解「表征漂移 × 恒定读出率」的灾难性遗忘）、`eta_readout=0.15`（现行口径）；
  - 稀疏路径下更新只触达存在的连接（`_csr_add_outer`），学习规则与稠密版逐条对应。

### 4.8 学习规则总表（全部局部，无反向传播）

| # | 规则 | 公式 | 作用 |
|---|---|---|---|
| 1 | k-WTA 竞争 | `s = top-k(normalize(u))` | 稀疏编码 |
| 2 | Oja 规则 | `Δw = η·y·(x − y·w)` | 稳定的 Hebbian 特征学习（防发散） |
| 3 | PC 误差规则 | `ΔW_dn = η·e ⊗ r_hi` | 生成模型拟合数据分布 |
| 4 | STDP 迹 | `Δw = η·(P_pre·post − P_post·pre)₊` | 时间因果结构学习 |
| 5 | 海马印迹 | `W_fast += η_h·p_out ⊗ p_in` | 一次性经验快速存储 |
| 6 | 皮层巩固 | `W_slow ← (1−η_c)·W_slow + η_c·W_fast` | 慢速统计学习（睡眠回放抽象） |
| 7 | 感知器读出 | `ΔW_ro = η·(t − y) ⊗ h`（softmax 版 `−η(p−t)⊗h`） | 仅末端使用监督 |
| 8 | 调制门控 | `η_t = η₀·σ(a·z(surprise))` | 全局可塑性调度 |

**稳定性设计**：Oja 归一化项防权重爆炸；STDP 与 PC 主干分别有 `w_max` / `pc_w_max`
截断；Hopfield 检索用 sign 吸引子保证收敛；稳态突触缩放拉回行范数；双速率分离避免快学习
破坏旧知识（灾难性遗忘的结构性对策）；临界期 + 突触修剪清除低效连接。

## 5. 认知层 M7–M13：面向 LLM 功能目标

> 在基础架构 M1–M6 之上，认知层使架构机制上覆盖 LLM 的四项核心功能：自然语言理解、
> 上下文处理、知识存储与调用、文本生成。**铁律合规**：全程无自注意力、无位置编码、
> 无堆叠层，每个机制都有神经认知对应。本文只给机制与对应；**实测结论见
> 《竞争力与脑同构性评估.md》与路线图文档。**

### 5.1 LLM 功能的类脑机制映射

| LLM 功能 | LLM 的实现 | 认知层的实现 | 认知对应 |
|---|---|---|---|
| 自然语言理解 | 自注意力 + 堆叠层学分布式语义 | M7 组合编码 + M2 层级压缩：字符 SDR 经 STDP 绑定为词/短语表示，预测编码层级逐级抽象 | 视觉/语言皮层的层级特征组织 |
| 上下文处理 | KV cache（无学习）+ 位置编码 | M8 情景缓冲（逐模式寻址 + 突触链时序）+ M10 分层摘要 | 海马情景记忆 + 前额叶分层工作记忆 |
| 知识存储与调用 | 参数隐式存储 + 注意力检索 | M9 语义关联图（三元组印迹）+ M12 联想链（多步激活） | 海马-皮层语义网络 + 联想扩散激活 |
| 文本生成 | 自回归 + 注意力条件化 | M11 生成解码器：下行预测通路反向展开 + WM 主题锚定 + 调制噪声采样 | 内言语与运动皮层生成通路 |
| 逐步推理 | 思维链提示（仍是注意力） | M12 联想链：检索结果回填 WM 作为下一线索，迭代展开 | 人类联想式推理（扩散激活理论） |

### 5.2 机制级替代（不是「不用 attention 的近似」，而是不同信息原理）

1. **自注意力 → 局部可塑性关联**：LLM 用全局成对相似度实现「任意位置关联」；认知层用
   **联想链**（检索→回填→再检索）与**情景缓冲索引**实现多跳关联——代价是逐步串行
   （对应人脑串行注意），收益是每步 O(活跃×m) 而非 O(T²·d)。
2. **位置编码 → 突触链时序**：「第 k 个位置」不存在于任何向量中，顺序即连接——时间信息
   由 **STDP 因果链**（先发-后发绑定）与情景缓冲的**链式回放**承载。
3. **堆叠层 → 层级预测编码 + 摘要层级**：抽象由 M2 预测编码层级（生成-识别闭环，非堆叠的
   残差流）与 M10 分层摘要（句/段/篇递归压缩）实现——每层是独立脑区式模块，有自己的
   记忆与调制。

### 5.3 模块要点

**M7 组合编码器（词汇涌现）** —— 字符 SDR 呈现时，STDP 链把共现字符绑定为词级表示；
词表示 = 该词字符序列在关联核中的激活轨迹终点。工程实现为**无词典统计分词**
（n-gram 频次 + 边界熵判据），词表由语料自动涌现。认知对应：视觉词形区（VWFA）的
组合调谐。实现见 `phdnet/word_encoder.py`、`phdnet/word_lm.py`。

**M8 情景缓冲（Episodic Buffer）—— 上下文的对应物** —— 逐模式寻址的事件序列存储。每个事件
印迹到 LTM 并在缓冲中形成 STDP 链；任意历史事件可作检索线索，链式回放恢复**顺序**。
对照 KV cache：KV cache 是无学习的原文堆叠；情景缓冲是**可学习、可补全、可链式回放**的
记忆——回忆是重构而非复制。

**M9 语义关联图（Semantic Graph）—— 知识的对应物** —— 三元组 (s, r, o) 以组合线索印迹
`W += η·outer(o, [s ; r])`；检索 `cue = [s ; r]` → 吸引子收敛 → o，**一次矩阵-向量乘，
无需注意力打分**。工程注记：实体表示必须用确定性哈希。

**M10 分层摘要（Hierarchical Summaries）** —— 句级 → 段级 → 篇级递归压缩，各层独立衰减率，
形成「细节易逝、要旨长存」的梯度。机制落在 M4a 的摘要槽（§4.4），三级层级为配置扩展。

**M11 生成解码器（文本生成）** —— 每步：WM 主题锚定 → 读出分布 p(next|state) → 调制噪声
采样（温度 τ 对应神经噪声/随机变异性）→ 生成 token 回填输入。自回归，但条件化机制是
WM 锚定而非注意力。

**M12 联想链推理引擎** —— `state ← WM; for r in 链: state ← query(state, r); state 回填 WM`。
每步是局部联想检索，结果作为下一步线索——与「思维链」功能同构但机制为扩散激活。

**M13 上下文漂移情景记忆** —— 上下文随经历缓慢漂移（`c ← ρ·c + (1−ρ)·item`）并印迹
「上下文 → 项目」；回忆时用当前上下文做**内容寻址检索**，回忆出的项目又驱动上下文继续
漂移 → **串行顺序回忆自然涌现**（TCM / CMR）。三个配套：① 事件边界触发回放；
② PFC 免衰减保持槽维持情节起始上下文；③ **DG 模式分离**为每段情景混入去相关编码
（决定性组件）。实现见 `phdnet/context_memory.py`。

### 5.4 架构层面的差距声明（机制 vs 能力）

架构层面，四项 LLM 功能都有机制对应物；能力差距主要在**经验规模**而非架构原理。
**这一节只作声明，不作能力宣示**——内置语料只有 2 万字符量级，与真实 LLM 的训练量差
8–10 个数量级。要把机制兑现成能力，需要（按序）：MB→GB 级语料、词级编码的实际训练、
10⁹⁺ 突触知识印迹、以及真实的算力预算。这些是工程与资源问题，**不受四条铁律约束**。

## 7. 精度体系

精度设计的目标是**学习精度**，其次才是访存量。本节只讲现状与机制解释；
**性能数字在性能文档**。

### 7.1 读出：`--readout-dtype` 默认 fp8（fp8 forward + fp16 更新）

- forward 用 **fp8_e4m3fn 副本**（1B 档 320 → 80 MB），**更新用 fp16 主副本**；
  `--fp8-refresh` 默认 8 步重建一次副本（量化成本摊到 N 步，N 越大越省，但副本越旧）；
- fp8 matmul **仅昇腾/CUDA 可用，CPU 自动回落 fp16**。

**动机是学习精度，不是省访存。** 机制解释：

- softmax 感知器的梯度是 `∂L/∂y = p − t`。对**非目标行**（`t_j = 0`），这个量是
  `p_j`，量级 **≈1e-6**——正是「压低不期望的类」这一侧的学习信号；
- **bf16 只有 7 位尾数**，在 1.0 附近的半 ULP ≈ **2e-4**，比 `|dp| ≈ 1e-6` **大两个数量级**
  → 更新被舍入直接丢弃；
- 结果：bf16 下学习规则**退化为「只提升目标行」的纯 Hebbian**，非目标行完全不更新。
  本机实测：fp16 主副本下 **5722 个**非目标行格点获得更新，bf16 下为 **0**；
- 反过来说，fp8 只用于 **forward**（推理方向不需要这个梯度精度），更新侧必须 fp16；
- **不是访存收益**：更新侧用 fp16 使总访存 **+42%**。任何「fp8 是为了省带宽」的说法都是
  错的——这是为学习精度付的代价。

### 7.2 M1 编码器：默认 fp64（平台差异）

- `--encoder-dtype` 默认 **fp64**；
- 原因：**昇腾 numpy GEMV 病态** → aarch64 走自写 numba 核（`_gemv_rows`），
  x86 走 BLAS。这是**平台差异**，不是算法选择；
- **迭代量全程 fp32**（GEMV 上采样后计算，top-k 归一化与学习增量不在低精度下做）；
- 平台差异铁律：M1 在 x86 用 fp32 快 1.80×、在昇腾**慢 70×**。**x86 的性能结论不构成证据。**
- 低精度存储（bf16/fp16）在 numpy/BLAS 路径下每次都要付一次上采样转换，
  可能比直接 fp32 GEMV 更慢——低精度只在 torch/NPU 路径上才有意义。

### 7.3 分词 onehot 缓冲：fp16

- 值只有 0 / 1，**fp16 无损**；1B 词表下每步缓冲/传输 208 KB → **104 KB**；
- 缓冲预分配复用（每步只写目标位并清掉上次的位，与 `np.zeros` + 置 1 逐位相同）；
- 消费侧（target_idx 路径与 softmax）按需要转精度，不受影响。

### 7.4 检查点：位模式存储

- `--ckpt-dtype` 支持 `fp8` / `bf16` / `fp16`，只压缩**检查点里的大矩阵**（读出 W 等），
  以**原始位模式**（uint8 / uint16）存储，加载侧按 `ckpt_dtype` **解码闭环**回计算精度；
- 理由：低精度**用于存储而非计算**。fp8 matmul 在部分 torch 版本不支持，
  拿它做训练计算需每步转换，反而更慢；而存储侧 fp8 体积直接降到 1/4 且无计算语义变化；
- **未知开放项**：bf16 / fp8 检查点的体积与加载耗时未测。

## 9. 附：部件 × 执行后端

| 部件 | 执行后端 | 并行方式 | 备注 |
|---|---|---|---|
| 词涌现（`_induce_length`） | numba nogil 核 | 层间线程池（各 L 独占一核） | 核内串行（`prange` 已回退：实测 1→6 线程提升在噪声带内，内存带宽饱和） |
| 词表全量扫描（锚点链） | numba nogil 核 | `ThreadPoolExecutor`（组间，零 pickle） | 小词表 CSR 二分 / 大词表边哈希自适应 |
| 语料解码 | 释放 GIL 的解码器 | 单进程内多线程 | 多进程只增内存，不增吞吐 |
| 分词（训练循环内） | 纯 Python / numba nogil 核 | — | 占端到端比例极小，不优先优化 |
| M2 预测编码栈 | numba CSR 核（事件驱动稀疏） | 行并行 `prange` | 融合核的 x86/昇腾方向相反，见 §4.2 |
| M3 STDP | numba CPU | 单核 | 逐突触状态，无法迁移到设备 |
| M4b 大容量表 | numba 事件驱动 + 在线 CSR | 单核 | dict 版仅供短跑/调试 |
| M6 读出 | `auto`：有加速器则 `AccelReadout`（torch 设备）→ 否则 numba CPU | 单设备（W 常驻）；多卡为读出列并行 | 未实现的配置（稀疏读出、两级读出等）**显式回落并记原因**，绝不「能跑但语义不同」 |

**为什么是这个组合**：numba 只能编译到 CPU 机器码（物理限制），所以「能上设备的部件」
必须用 torch 写。当前只有读出满足（纯矩阵、W 大、每步通信量小）。其余部件要么是变长
字符串（分词/词表扫描，设备不划算且占比极小），要么是事件驱动稀疏结构（迁移会丢机制）。
这是**当前的诚实边界**，不是未做清单。

## 10. 附：词表与可复现性

**词表快照**：词表一确定就落盘 `outputs/models/vocab_<preset>_<data>.json`（权威）
+ `.txt`（人读镜像），训练崩溃/中断也不丢；下次 `--vocab-file <同名>.json` 直接复用。

- 快照**必须同时存两个集合**：`words`（token 词表 = 读出层行数 = `n_readout`）与
  `seg_vocab`（分词器候选集，训练时是涌现词表，通常是真子集）——用 token 词表代替
  候选集会让分词结果与训练不一致（**静默降质**）；
- 词表可能含**跨行 token**（如 `"\n的"`），故 JSON 为权威格式（纯文本每行一词会把它切碎）；
- 推理侧自动定位同目录 / `outputs/models/` 的快照并**交叉校验**（比对 `tok_tokens`），
  不一致即报错退出——防「用错词表静默降质」。

**词表来源三选一**（优先级从高到低）：① `--resume` + 检查点存在 → 跳过构建，用检查点内
的 `tok_vocab` / `tok_tokens` / `tok_max_len`；② `--vocab-file` → 外部词表；
③ `--vocab-scan head|full` → 扫描（head = 采样文本，full = 全量锚点链）。

**查找结构按词表规模自适应**：边数 ≤2 万走 **CSR 二分**（小词表下二分常数更小）；
>2 万走**边哈希**（键 = `node·2¹⁶ + char`，槽位经 Knuth 乘法混合——直接取低位会让
「同字不同节点」全部撞槽、探测退化）。两条路径**逐位等价**（同一 trie、同一最长匹配规则），
由专项对拍保证。

**设备张量兼容**：参数统计与检查点存档统一把 numpy / torch（含 CUDA·NPU·ROCm 设备张量）
转 numpy 再统计。动机：昇腾机器实测 `np.asarray(npu_tensor)` 会直接抛错，会让参数统计与
检查点保存双双失败。
