## 4. 写文档的顺序

```bash
# 1. 确认要写的当前数字与代码一致（数字只在《现状速查》/《性能文档》两处有权威出处）
# 2. 只改你负责那一份；越界（改了别份「只写」范围的内容）算错
# 3. 收尾四步（详见《扩展指南》）
python tools/run_gates.py --jobs 4        # 门禁
python tests/run_tests.py fast            # fast 回归
```

## 5. 术语口径（全局统一）

| 术语 | 含义 |
|---|---|
| **ms/tok** | 毫秒 / token。**必须带平台与档位**，x86 与昇腾的数字**不可混用** |
| **`accel:xxx@device`** | 读出真在加速器上；`backend=numba-cpu(回落)` = **没上设备** |
| **读出已上设备** | 唯一证据是日志里的 `读出 X ms/tok（后端@设备）` 行 |
| **`accel:auto`** | 设备串解析结果（auto = 择优命中）；**不等于**已在设备上算 |
| **逐位一致** | 浮点结果按位相同。跨设备/跨库只能用**容差**，不能要求逐位 |
| **容差判据** | 判「两个实现等价」的数值阈值。**基线必须经过同一精度舍入**，否则会得到反向假阳性 |
| **`probe_PPL`**（固定探针 PPL） | **A/B 唯一判据**。训练流 sliding PPL 波动 ±20%，**不可用作判据** |
| **`segments(win)`** | 判性能**一律看滑窗**；`segments(cum)` 是含 JIT 冷编译的历史平均 |
| **假占用** | 设备占用 90%+ 但 `aicore_time≈0` → 指标虚高，不是真实算力利用率 |
| **段名** | `M1_encode` / `M2_infer` / `M3_pred` / `M4a_wm` / `M4b_ltm` / `M5_mod` / `PC_learn` / `STDP_learn` |
