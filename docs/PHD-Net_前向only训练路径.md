## 0. 一句话

市面上的 forward-only（无反向传播）训练路径解决的核心问题是
**「没有反向梯度时，如何把任务信号送到中间层」**。PHD-Net 已经是无反向传播架构，
但**任务信号只到达 M6 读出，主干 M2 只学无监督重构**——本路径补的就是这一缺口。

**P211（fhz 2026-10-31 指示「默认采用 forward-only，旧的非 forward-only 可以删去」）**
之后，本路径是**默认且唯一**的任务信号注入通道：

- `cfg.forward_only` 默认 **True**；
- CLI 的 `--forward-only`（开启）已删除，只剩 `--no-forward-only`（关闭）；
- 旧的「非 forward-only 路径」**不再是并列模式**，而是本路径的一个**特例**：
  `--forward-only-eta 0` 即完全等价于旧行为（门禁 C3b 用训练轨迹摘要逐位验证）。

## 1. 调研：市面上的五条 forward-only 路径

检索时间 2026-10-31。**下表是方法机制的事实记录，不是本项目的实现承诺。**

| 方法 | 出处 | 核心机制 | 层间信用分配方式 |
|---|---|---|---|
| **Forward-Forward (FF)** | Hinton, 2022 | 数据与标签假设拼接后各自前向，比对各假设的「goodness」 | 每层只看自己的激活与一个标量 goodness 差异 |
| **Forward Projection (FP)** | Nat Commun 2026, s41467-026-69161-1 | 用**随机非线性投影**把标签投影成各层膜电位目标；局部损失用**闭式回归**求解 | 目标从标签经固定随机投影生成，逐层独立 |
| **Forward Target Propagation (FTP)** | arXiv 2506.11030 | 第二次前向扫描，用固定随机矩阵 G 从输出预测与目标标签估计逐层目标 | τ1 = σ(Gy) − σ(Gh_L) + h1，之后 **τi = σ(W_i·τ_{i−1})**（复用同一套前向权重递归） |
| **NoProp** | arXiv 2503.24322 | 每层独立学习去噪一个带噪标签 | 每层独立去噪，无层间信用分配 |
| **Sigprop** | 前向信号传播 | 把全局学习信号投影进网络成为层目标 | 前向投影 + 逐层局部学习 |

另有相关工作 **Direct Feedback Alignment (DFA)** 与 **DRTP**（用随机反馈矩阵把
输出误差直接投给隐层）：FTP 论文将其列为对比基线，并指出 DFA「依赖全局误差信号、
冻结网络动力学」，DRTP「准确率与可扩展性较低」。

### 1.1 抽取出的共同内核

三条，本路径逐条对齐：

1. **不使用反向传播** —— 梯度不沿层间回传。
2. **层目标由「标签 → 固定随机投影」生成** —— 投影矩阵**固定不训练**
   （FP/FTP 都用固定随机矩阵 G），故**不存在权重对称性 / 权重传输
   （weight transport）问题**。这是 forward-only 相对 BP 的结构性优势。
3. **每层用自己的局部目标做局部学习** —— 损失只看本层激活与本层目标。

### 1.2 逐条判断「能不能融入 PHD-Net」

| 方法 | 判断 | 理由 |
|---|---|---|
| FF | ❌ 不直接采用 | 需为**每个候选标签**做一次前向。PHD-Net 生产词表 **51,962** → 每 token 5 万次前向，不可行 |
| NoProp | ❌ 不直接采用 | 逐层去噪带噪标签需要每层一套「标签嵌入 + 噪声调度」，与 PHD-Net 的六机制无对应，且不解决「任务信号到主干」的问题 |
| **FP** | ✅ **采用其目标生成内核** | 「标签 → 固定随机投影目标」正是本路径需要的 |
| **FTP** | ✅ **采用其目标递推内核** | 「沿模型自己的权重递推层目标」避免了引入额外反馈矩阵，正好契合 PHD-Net 已有的下行生成权重 |
| DFA / DRTP | ❌ 不采用 | DFA 依赖全局误差信号；DRTP 准确率低。PHD-Net 的误差信号在读出末端已是「全词表 one-hot」，直接回投会退化成读出权重的转置（即 BP） |

## 2. 本项目的实现（P210）

### 2.1 落点

**M2 的下行生成权重（dn0 / dn1）**。动机与既有机制的关系：

- M2 此前只学**无监督重构**（PC 误差）+ 恒等初始化；P194 起给生成权重开了
  `eta_pc=0.02` 的发育窗口（学「当前输入的重构」）。
- T1.2 `pc_predictive_target` 已把生成权重的目标改成「**上一时刻的表征**」
  （时序预测），仍是**无监督**的。
- P210 把目标再推一步：**换成「下一 token 的固定随机码」** —— 任务信号第一次
  到达主干，且**全程无反向传播**。

### 2.2 机制

```
目标生成（一次前向，无回传）
    τ_r1 = σ(Proj(label))          ← FP 内核：标签 → 固定随机投影
    τ_s0 = σ(dn0 · τ_r1)           ← FTP 内核：沿模型自己的权重递推到更浅一层

局部学习（逐层独立，无跨层梯度）
    dn1 += η·(τ_r1 − dn1·r2) ⊗ r2
    dn0 += η·(τ_s0 − dn0·r1) ⊗ r1
```

- `Proj` 是**固定随机映射**（splitmix64 哈希按需生成，不存矩阵 —— 稠密投影表
  在 51,962 词表 × 1024 维会是数百 MB）。
- 稀疏口径与既有 PC 学习一致：**只更新已存在的边**（CSR 外积），不新增连接、
  不改拓扑（稀疏是架构原则）。
- 递推用的是 `dn0` 自己的稀疏 matvec，**不需要任何额外反馈矩阵**。

### 2.3 为什么 τ 是「随机码」而不是「正确答案」

**必须如实说明**：固定随机投影**不承载标签语义**。同一个标签永远给同一个方向，
不同标签给不同方向，但这个方向与词义无关。

它的作用是提供一个**非退化、逐层可区分**的目标方向。由此产生的直接后果是：
**下行生成权重会学到「从当前状态预测下一 token 的随机码」** —— 即生成权重成为
「未来预测器」。这与预测编码框架里生成权重的既有语义（T1.2 预测下一时间步表征）
同源，区别只在于目标从「上一时刻表征」换成了「前向only 的标签随机码」。

因此：**收益必须由 `probe_PPL` A/B 判定，不得先验断言更好。**

### 2.4 为什么不采用 FP 的闭式回归

FP 的闭式回归需要**整数据集统计**（对偶/核方法），与本项目的**逐 token 流式**
铁律（README §2 铁律③）冲突。本路径保留 forward-only 的**信用分配内核**
（固定随机投影 + 逐层目标 + 局部匹配），把「闭式求解」换成**流式增量**版本：
每步只用当前 token 的 (h_i, τ_i) 做一次局部更新。**这是有意的取舍。**

### 2.5 约束

- **不触碰上行识别权重 up0/up1** —— P198 实测 `eta_oja>0` 在生产规模正反馈发散
  （3000 步 probe_PPL 9.1e11），上行必须保持只读。本路径只改下行生成权重
  （`eta_pc` 那一侧，P194 实测该侧安全）。
- **P211 起默认开启**（`cfg.forward_only=True`）。旧路径不再是并列模式，而是本路径的
  **特例**：`--forward-only-eta 0` 时训练轨迹**逐位不变**（门禁 C3b 用摘要验证）；
  `--no-forward-only` 则连投影器都不构造（零开销，门禁 C1c）。
- 只在**有监督信号**时执行（无标签就没有层目标）。

## 3. 用法

```bash
# 默认就是前向only 路径（P211 起默认开启，无需任何开关）
python train/train.py --preset 1b --data pretrain

# 退回旧行为（等价于删掉本路径）：层目标学习率设 0
python train/train.py --preset 1b --data pretrain --forward-only-eta 0

# 关掉整条路径（等价于 eta=0，但连投影器都不构造）
python train/train.py --preset 1b --data pretrain --no-forward-only

# 调层目标匹配学习率（默认 0.01，乘以 PC 的调制缩放）
python train/train.py --preset 1b --data pretrain --forward-only-eta 0.02

# A/B 判据：必须用 probe_PPL（sliding PPL 信噪比仅 0.40，测不出 <20% 的差异）
python train/train.py --preset 1b --data pretrain --remote-data \
    --probe-every 1000 --probe-tokens 2048
```

| 开关 | 默认 | 说明 |
|---|---|---|
| `--no-forward-only` | 关（即 forward-only **开**） | **关闭**整条路径（连投影器都不构造）。P211 起 forward-only 是默认 |
| `--forward-only-eta` | `0.01` | 层目标匹配学习率（乘 PC 调制缩放）；**0 = 完全等价旧行为** |
| `--forward-only-gain` | `1.0` | 目标随机码增益（再经 tanh 压到 (-1,1)） |
| `--forward-only-seed` | `0` | 固定随机投影的种子偏移（0 = 跟随 `--seed`） |

## 4. 实测

### 4.1 P210 首测（显式开启时，未达显著）

**口径**：smoke 档（width=256）、`--data cc_traces`、2000 token、x86 8 核本机、
`--probe-every 1000 --probe-tokens 512`（探针文本 = 冻结 `eval_corpus/internal_corpus.txt`
的只读前向，n_tok=84）。**判据 = probe_PPL**（README §4 要求）。

| token | 基线 probe_PPL | `--forward-only` probe_PPL | 差值 |
|---|---|---|---|
| 1,000 | 18,624.3004 | 18,565.5264 | **−0.32%** |
| 2,000 | 12,029.6655 | 11,726.1201 | **−2.52%** |

`[METRIC] ms_per_token`：基线 8.24 → 开启 8.18（本机 x86；不代表昇腾）。

**诚实结论**：
- 方向为正（两次探针都更好），但**幅度远低于项目判据**（README §4：任何 <20%
  的差异都测不出来；sliding PPL 信噪比仅 0.40）。**不能据此宣称收益。**
- 本机是 x86 8 核 **无 NPU**，且 smoke 档仅验管线 —— **生产档（1b、昇腾、
  百万 token）未测**。

### 4.2 P211 复测（默认开启后；smoke 档 sliding PPL 对照）

**口径**：smoke 档、`--data cc_traces`、3000 token、x86 8 核本机，4 次取最优。

| 配置 | final_ppl | ms/tok（中位） |
|---|---|---|
| **forward-only 开**（P211 新默认） | **13,017.891** | 8.12 |
| forward-only 关（`--no-forward-only`） | 13,355.328 | 7.61 |

- 方向**明确为正**：**PPL 改善 2.53%**（13017.891 vs 13355.328）。
- ⚠ **仍低于项目 <20% 判据** → 本机 smoke 档**不能据此宣称收益**；
  真正的判据仍需**服务器 1b 档 probe_PPL A/B**。
- ⚠ forward-only 本身有**开销**（FO_learn 段 0.32–0.44 ms/tok）——
  在本机 smoke 档它**换来的 PPL 改善与开销相抵**（8.12 vs 7.61 更慢）。
  这正是「收益必须由服务器 A/B 判定」的原因：若生产档收益不显著，
  应把 `forward_only_eta` 调小或设 0。

### 4.3 附带修复：探针从未真正生效

本次 A/B 准备过程中发现一个**既有缺陷**（与 forward-only 无关）：
`train/train.py` 的 `sys.path` 只加了 `tools/`，而 `probe_nll` 来自
`tools/eval/ppl_probe.py` → `--probe-every` 永远走 except 分支打印
「探针不可用（不影响训练）」。**即 README §4 规定的 A/B 判据（probe_PPL）
在生产入口上从未真正跑起来**，所有 A/B 都退化成了 sliding PPL。

已修（把 `tools/eval/` 加入 `sys.path`）。修复后本节的 probe_PPL 才是真实判据。
**该修复对历史结论的影响**：历史上所有用 sliding PPL 做的 A/B 都应视为
**低信噪比**证据（README §4 已如实说明该口径），本修复不追溯改判它们。

## 5. 门禁

`tests/gates/gate_forward_only.py`（P210 新增；**P211 更新为 30 项**）：

| 组 | 内容 |
|---|---|
| A | 固定随机投影：确定性、区分性、值域、无溢出告警、标签越界报错 |
| B | 层目标学习：目标递推维度与值域、**不触碰上行**、稀疏性（CSR 行宽不变）、目标匹配方向、eta=0 零贡献 |
| C | 接线与零回归（P211 更新）：**默认开启**（C1a/C1b）、显式关闭不构造投影器（C1c）、关闭时同种子逐位一致（C2a）、开启时轨迹确实改变（C3）、**eta=0 轨迹 == 旧路径轨迹**（C3b，P211 新契约）、配置 fail-fast（C4）、CLI 只剩 `--no-forward-only`（C5） |

跑法：`py -3.14 tests/gates/gate_forward_only.py`

**C3b 是 P211「删旧路径」的实现方式判据**：它断言「forward-only 且 eta=0」的
训练轨迹摘要与「显式关闭 forward-only」的轨迹**逐位相同** —— 即旧路径没有另起
一套代码，而是被表达成新路径的特例。

`tests/gates/gate_cpu_opt_p211.py`（P211 新增，15 项）覆盖本路径的性能改造
（融合核逐位等价、不触碰上行、稀疏性、稳态缩放只作用于下行），
详见 [CPU 性能优化实录](PHD-Net_CPU性能优化实录_P211.md)。

## 6. 术语口径

| 术语 | 含义 |
|---|---|
| **前向only / forward-only** | 训练不使用反向传播、梯度不沿层间回传的方法家族 |
| **层目标 τ** | 由「标签 → 固定随机投影」生成的目标激活；**不含标签语义** |
| **固定随机投影** | 投影矩阵固定、不训练、不依赖模型权重 → 无 weight transport 问题 |
| **目标匹配** | Δw = η·(τ − h) ⊗ pre；局部梯度，不跨层回传 |
| **流式增量（vs 闭式回归）** | 每步只用当前 token 更新，不用整数据集统计（守逐 token 铁律） |
