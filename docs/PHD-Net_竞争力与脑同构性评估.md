# PHD-Net 竞争力与脑同构性评估

> **适用范围**：与 Transformer / MoE 的**结构性对比结论**，以及与人脑的**逐机制同构对照**。
> **不写**：任何性能数字（唯一出处 = `docs/PHD-Net_性能评估与迭代方案.md`）、机制实现细节
> （=《PHD-Net_架构设计.md》）、加速器踩坑（=《PHD-Net_硬件后端适配报告.md》）。
> **数据截止**：2026-09-30。**诚实前提**：本文一切"竞争力"判断均在**单机 CPU 资源受限**与
> **窄任务**前提下成立；规模外推是**方法与假设**，PHD-Net 目前**没有实测缩放曲线**可援引。

---

## 一、结论先行

| 问题 | 结论 |
|---|---|
| 能否对标前沿 MoE 大模型的通用语言能力？ | **不能，且差距不由参数容量决定。** 差距来自经验量与表示学习机制；把容量放大只会放大容量，不会自动转化为能力 |
| 与 Transformer 的差距是「调优」问题还是「结构」问题？ | **结构问题。** 无自注意力 / 无位置编码 / 无层堆叠是铁律，不是待优化项；因此也不存在「补齐注意力就能追平」的路径 |
| PHD-Net 的强项是什么？ | **单步触碰量小、逐 token 在线学习、无灾难性遗忘、本机可跑**——这四项与规模无关，是结构性差异 |
| 放大容量的风险？ | 会。**容量单向扩容是已被实测证伪的路径**；扩容必须同时解决"谁来用这些突触" |
| 与人脑是"相同"还是"同构"？ | **机制同构，不是结构相同。** 12 个机制都有明确神经认知对应，但规模差 4–5 个数量级，且稀疏性上**有一处明确欠账**（§四） |
| 最诚实的一句话 | PHD-Net 不缺算力预算，**缺的是把容量转成能力的可塑机制**；脑同构的账目前**只还了六成**（M6 读出仍 100% 稠密） |

## 二、机制层同构对照（12 机制 + M6）

下表只列**机制 ↔ 神经认知对象**的对应关系，不评价实现好坏（实现见《架构设计》）。
「默认」列指 `phdnet/config.py` 中的开关默认值。

| # | 机制 | 神经认知对应 | 1B 档实际口径 | 默认 |
|---|---|---|---|---|
| 1 | **M1 稀疏分布式编码**（k-WTA） | 皮层稀疏编码：1–5% 激活率，稀疏表示换高容量 | 输出 **12.5%** 稀疏（`k_sparse = w//8`） | 开 |
| 2 | M1 可学习稀疏词典（`learnable_encoder`） | 初级皮层 simple cell 感受野的经验学习 | 慢调 W_enc（Oja + 行范数双约束） | 关 |
| 3 | **M2 预测编码主干** | 皮层预测编码：高层生成低层、误差回传精炼 | 4 层 CSR 栈，误差驱动精炼 | 开（`eta_pc` 在 1B 档**冻结为 0**） |
| 4 | M2 结构性稀疏连接（CSR） | 皮层组织原则：dense representation + **sparse connectivity** | `conn_k = n//8` → **12.5%** 连接率 | 开（`sparse_conn=True`） |
| 5 | **M3 STDP 时侧向关联** | 突触可塑性的时序因果律（前摄/后摄不对称） | `m_lateral=16` → **1.56%** 出边，**只走 numba CPU** | 开 |
| 6 | M3 稳态缩放 / BCM 元可塑性 / 逐突触自适应 LR | 突触稳态（Turrigiano）、BCM 滑动阈值、局部二阶矩归一 | 三开关分立，**自适应 LR 与 torch 后端不兼容** | 全部关 |
| 7 | **M4a 工作记忆** | PFC 漏整合（leaky integrate-and-fire）+ 有限槽位 | `gamma_wm=0.85` 衰减 + 门控写入 | 开 |
| 8 | M4a 摘要槽 / 内容寻址写入 | PFC 的压缩/摘要与内容寻址聚合 | `wm_summary_every`（0=关）、`wm_content_address` | 关 |
| 9 | **M4b 大容量事件驱动稀疏表** | 稀疏长时记忆：容量靠**生长**而非稠密预分配 | 1B 档 2²⁴×**72** = **1,207,959,552** 突触容量 | 开 |
| 10 | M4b 分期睡眠 SWS/REM + downscaling | 睡眠驱动的突触巩固与稳态缩放（Tononi & Cirelli） | `sleep_downscale=0.9` | 关 |
| 11 | **M5 神经调制** | 神经调质：ACh 编码/检索、NE 新颖性、DA 巩固、5-HT 耐心 | 库默认单标量；四通道版 `multi_modulation` | 单标量开 / 四通道关 |
| 12 | E/I 突触类型 + 发育临界期修剪 | 皮层 ~80% 兴奋 / 20% 抑制；发育可塑性窗口关闭 + 突触消除 | `ei_ratio=0.2`、`crit_rate=0.001`、`prune_threshold=0.01` | 全部关 |
| **M6** | **读出**（稀疏感知器 + softmax） | 群体编码输出：下游群体读出分布式表征 | 1B 档 **100% 稠密**（`readout_conn_k=0`）→ **架构欠账** | 稠密 |

**读法**：1–5、7、9 是**默认开启且已进入生产路径**的机制；6、8、10、11（四通道）、12
是**默认关闭**的机制（铁律四：行为变更以 config 开关承载且默认关闭），它们在
`tests/checks_core.py::t_brain_homologues` 里与主路径一起做零崩溃自检，但**没有生产实测结论**。
M6 那一行是全表唯一**方向相反**的：它把前 11 项攒下的稀疏性在出口处还回去了。

## 三、与 Transformer 的结构性差异

不是"我们更省"，而是**四个不可互换的结构选择**：

| 维度 | Transformer | PHD-Net | 性质 |
|---|---|---|---|
| **Token 混合** | 自注意力：每个 token 与全序列交互 | **无自注意力**。混合走 M4a 漏整合 + M2 层级预测 + M3 时侧向 | 铁律①，**不可补齐** |
| **顺序信息** | 位置编码 / RoPE | **无位置编码**。顺序由网络**状态**（WM / STDP 迹 / LTM 印迹）承载 | 铁律① |
| **深度** | N 层堆叠，逐层精炼 | **无堆叠层**。深度 = 状态演化的时间轴，不是层数 | 铁律① |
| **计算粒度** | 可批处理（序列维并行） | **逐 token 状态演化**：状态跨 token / shard / epoch 连续演化，读出 W 每步原地更新 → **不允许批处理** | 铁律③ |
| **条件化窗口** | 固定窗口 = 上下文长度 | 无固定窗口；条件化 = 状态，理论上不截断 | 结构性 |
| **稀疏发生在哪** | 稠密注意力 +（MoE 的）**专家路由**稀疏 | **突触存在性**稀疏：事件驱动的局部触碰 | 两者都稀疏，维度不同 |

推论（诚实）：

1. **PHD-Net 拿不到 Transformer 的并行红利**。逐 token 串行 + 每步可并行工作量小，
   这直接导致"大机器吃不满"——论证见《PHD-Net_并行与加速架构分析.md》，本文不复述。
2. **PHD-Net 也不该拿 Transformer 的评价标准**。在固定 benchmark 上比 MMLU 一类
   知识/推理任务，对一个无注意力、无位置编码、逐 token 的词级联想续写器是不公平比较。
   公平的比较维度是：**单步触碰量、在线学习能力、状态容量、无遗忘**。
3. **与 MoE 的可比性**：MoE 稀疏在"专家路由"（每 token 激活 top-k 专家），
   PHD-Net 稀疏在"事件驱动的局部突触"。二者都可用"存储参数 / 每步激活量 /
   稠密可训练参数"三口径记账；**PHD-Net 的稠密可训练参数远小于其存储容量**，
   因为只有被触碰的突触才更新——这是设计选择，不是缺陷，但也意味着
   **容量利用率必须单独度量**。

## 四、稀疏性是脑同构的核心欠账

人脑的稀疏性是**结构性的**（不存在的突触不存储、不计算），量级参考：

| 口径 | 数值 | 来源性质 |
|---|---|---|
| 人脑连接率 | **~2×10⁻⁸** | 公开神经科学量级，引用 |
| 每神经元突触数 | **约 1744 条**（皮层锥体细胞量级） | 引用 |
| 皮层稀疏发放率 | 1–5% | 引用 |

PHD-Net 1B 档各机制的稀疏口径：

| 机制 | 稀疏口径 | 与人脑的差距 |
|---|---|---|
| M1 编码 | 输出 **12.5%** 稀疏 | 高 2–3 个数量级（但方向正确） |
| M2 主干 | **12.5%** 连接率 | 高 6–7 个数量级 |
| M3 STDP | **1.56%** 出边 | 方向正确，量级仍高 |
| M4b 大空间表 | **事件驱动**，只为共激活对生长突触 | 机制上最接近人脑（生长而非预分配） |
| **M6 读出** | **100% 稠密** | **欠账：架构级偏离** |

**明确结论**：M6 读出是**当前架构唯一方向相反的机制**。前 11 项把连接率压到 12.5% /
1.56% / 事件驱动，出口却是一个 `V×H` 的稠密矩阵（1B 档 51,962×3,072 =
159,627,264 个数，占总容量的 11.650%）。这不只是"多算了"，它还意味着：

- 读出的访存量决定了端到端步时（见《性能评估与迭代方案》，本文不复制数字）；
- 稀疏读出开关（`readout_conn_k > 0`，CSR 承载）**已设计但未走通生产**，
  加速后端对它显式 fail-fast 回落。

**这是"100B 之前必须先拆的雷"里排第一的那一条。** 幂律稀疏化方案已设计未实施。

## 五、规模与外推：只写方法与假设

**明确声明：PHD-Net 没有实测缩放曲线。** 本节只给方法与假设，不给编造的 PPL 数字。

外推必须声明三件事，缺一件就不可比：

1. **口径绑定**。PPL 锚点只有一组有效：**4K 段 394.4687 / 全语料 359.2603**
   （256 维栈、`eta_readout=0.15`、2026-09-28 换中文维基语料后重测）。更早的
   78.16 / 90.2480 / 73.1166 属**旧语料口径**，只存于 git 历史，**不可与新锚点混用**，
   更不可用来支撑外推曲线。
2. **同 fraction、同机器、同数据才可比**。远程语料是分片级前缀抽样
   （`--remote-fraction`，默认 0.3），改 fraction 等于换数据分布；跨 run 比 PPL
   前必须先对齐 `data / remote / remote_fraction / lang / 分片数`。
3. **外推是情景，不是预测**。已知的历史事实是：在**固定数据预算**下放大参数，
   PPL 反而变差（典型欠训练效应）——这说明"容量 → 能力"不是自动的。
   因此任何 100B 情景都必须同时写明**经验量预算**与**谁去触碰这些突触**。

**1B 档容量实算**（`train_1b/config_1b.py::capacity_report` 同口径，分母 = 总容量
1.370e9）：

| 组成 | 占比 |
|---|---|
| M4b 大空间表 | 88.158% |
| M6 读出（稠密） | 11.650% |
| M1 编码器 | 0.153% |
| M2 主干 CSR | 0.038% |
| M3 STDP | 0.001% |

注：更早文档里的 1.317e9 是 `big_ltm_m=60` 时代的值，**已作废**。

**放大路径的三个候选，各自带一个未验证假设**：

| 路径 | 未验证假设 |
|---|---|
| 扩 M4b 神经元数（30b 档已定义为 2²⁹×56 ≈ 30.3B） | 「更长的记忆」能变成更好的语言建模；访存与步时随容量线性放大 |
| 稀疏化 M6 读出（幂律稀疏） | 稀疏读出不损失读出层的表达力；**当前加速后端未实现** |
| 加密表征 / 扩经验量 | 现有在线机制能吃下更多经验量而不遗忘——**这一条最没有证据** |

## 六、诚实的短板清单

| 短板 | 性质 | 现状 |
|---|---|---|
| **M6 读出 100% 稠密** | 架构欠账 | 幂律稀疏化已设计未实施；加速后端对稀疏读出 fail-fast |
| 1B 档表征冻结（`eta_pc=0`） | 实测取舍 | 多轮实测最优解，但意味着**主干几乎不再学新表征**，可塑性只落在 M3/M6 |
| 机制多而**多数默认关闭** | 工程现实 | 12 个机制里 6 个默认关；它们只有零崩溃自检，没有生产结论 |
| 无实测缩放曲线 | 方法论缺口 | 任何规模结论都只能写成假设 |
| 缺可比 benchmark | 评价缺口 | 与前沿模型**无法**在同一张能力表上比较；本文因此不做能力排名 |
| 逐 token 串行 | 铁律③的代价 | 大规模下吃不满算力，是架构性而非实现性 |
| 语料构成存疑 | 数据问题 | 远程分片实测中文仅 2%，与早期记录矛盾（待核，见 `datasets/README.md`） |
| GitHub 侧 CI 仍红 | 工程债 | 两套 CI（`.gitcode/`、`.github/`），无 Jenkinsfile |

**不做的事**：本文不给"预计 N 年追上 X"式预测，不给无平台的加速倍数，不引用旧 PPL 锚点。
