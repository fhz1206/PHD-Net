## 一、结论摘要

| 问题 | 结论 |
|---|---|
| 与 Transformer 的差距是「调优」问题还是「结构」问题？ | **结构问题。** 无自注意力（铁律①，`phdnet/model.py` 中不存在 Q/K/V 投影）+ **无梯度** + **无 batch 维**（铁律③）三条同时成立，**没有任何调参路径能同时补齐** |
| 最根本的差异是哪一条？ | **逐 token 语义**。状态跨 token / shard / epoch 连续演化、读出 W 每步原地更新 → 训练样本无法批处理。这不是实现保守，是语义前提 |
| PHD-Net 的长程依赖靠什么承载？ | 不是注意力，而是**稀疏 CSR 预测编码（M2/M3）+ 大容量事件驱动稀疏表（M4b，海马体式内容寻址索引）**。载体是**状态与突触**，不是 QKV |
| 与 MoE 的关系 | **只有"稀疏"这一层相似，路由性质相反**。MoE gating 是**学出来的**；PHD-Net 的 k-WTA 与 CSR conn_k 是**发育期随机 + 稀疏先验**固定的，**路由不学习**。这是"免训练路由"换来"失去自适应" |
| 能否对标前沿 MoE 大模型的通用语言能力？ | **不能，且差距不由参数容量决定。** PHD-Net 1B 档 99.24% 的容量是事件驱动大空间表；把它放大到 30B 只放大容量，不自动产生能力（§五） |
| 与人脑是"相同"还是"同构"？ | **机制同构，不是结构相同。** 六机制都有明确神经认知对应物（§三），但规模差约 5 个数量级，且**稀疏性仍有一处明确欠账**：读出是 4.2% **均匀** k-conn，不是幂律异质分配（§六） |
| 速度提升是免费的吗？ | **不是。** 低精度读出会丢弃感知器 `p − t` 的非目标行更新（实测保留率 fp32 99.95% / fp16 26.67% / bf16 5.79%）→ 退化为纯 Hebbian。这是**速度 vs 学习规则正确性**的实测取舍（§六） |
| 最诚实的一句话 | PHD-Net 不缺算力预算，**缺的是把容量转成能力的可塑机制**；脑同构的账目前**只还了六成半**——出口的异质稀疏化实现了但没接线|

## 二、与 Transformer 的结构性差异

不是"我们更省"，而是**五个不可互换的结构选择**。其中第一条是根，其余四条是它的推论。

### 2.1 根差异：逐 token 语义 ⇒ 无 batch 维

`PHDNet.step()` 是**单时间步**接口（`phdnet/model.py:204`）。工作记忆槽位强度、STDP 突触迹
（`t_pre`/`t_post`）、LTM 突触、调制器 Welford 统计量、`step_count`、**读出 W** 全部跨 token
连续演化，且读出 W **每步原地更新**（`phdnet/readout.py:1154-1155`）。因此：

- 训练侧状态**永不重置**——`train/train.py:719` 打印
  `"[context] state never reset (WM/STDP/LTM carried continuously across samples/shards/epochs)"`；
  跨 epoch 也不重置（`train/train.py:805`），只有第一步的 `prev` 链接被切断（`p2 = None`）。
- 唯一例外是读出的 `minibatch_size` 梯度累积（`phdnet/config.py:277`），它只累积**梯度**、
  不改变 token 推进的逐步语义，且**默认 1 = 关闭**。
- 评估路径用 `readonly=True` 冻结所有持久状态（`model.py:211-213`）。

**后果**：Transformer 的训练吞吐来自"序列维并行 + 一次前向算一整批"；PHD-Net 每步的
可并行工作量是一个 token 的触碰量。**这不是实现缺陷，是语义的必然代价**（§六）。

### 2.2 无梯度：学习规则是局部的、在线的

源码中**不存在**任何 `backward` / `requires_grad` / `torch.optim` 路径
（`grep -rn "backward|autograd|requires_grad|torch.optim" phdnet/ train/ tools/` 无命中）。
可塑性只有三种，全部**局部**：

| 机制 | 规则 | 出处 |
|---|---|---|
| M6 读出（softmax 感知器） | `ΔW = −η·(p − t)⊗h`，`nll = −log p(correct)` | `readout.py:1147-1155` |
| M3 STDP | 三因子时序规则：`Δw ∝ η_eff · f(Δt)`，`η_eff = mod_scale × ne_gain × dev` | `plasticity.py:64-125`、`model.py:440-445` |
| M2 / M1 | Oja + 行范数双约束（**1B 档 `eta_pc=eta_oja=0` 冻结**） | `sparse_pc.py`、`config_1b.py:77` |

读出的 `p − t` 是**感知器局部误差**，不是链式法则的梯度——误差**不反传主干**
（监督信号仅存在于最末端）。M3 的第三因子 `ne_gain` 来自 M5 神经调制（`model.py:440-441`），
这才是完整的"三因子"结构。

**与Transformer 的量级差异**：Transformer 的一切能力都建立在"可微 + 反向传播 + 大规模
梯度优化"这条链上；PHD-Net 这条链**从设计上不存在**。因此训练效率上的差距是
**结构性的**，不是学习率、batch size 或优化器能解决的（§六）。

### 2.3 五个维度对照

| 维度 | Transformer | PHD-Net | 性质 |
|---|---|---|---|
| **Token 混合** | 自注意力：每个 token 与全序列交互（Vaswani et al. 2017, arXiv:1706.03762） | **无自注意力**。混合走 M2 层级预测编码 + M3 时侧向 + M4a 漏整合 | 铁律①，不可补齐 |
| **长程依赖载体** | QKV 矩阵的内容寻址加权求和 | **稀疏 CSR 预测编码 + 大容量事件驱动稀疏表**（M4b，2²⁴×72 = 1,207,959,552 突触容量，1b 档） | 载体不同，非程度差异 |
| **顺序信息** | 位置编码 / RoPE | **无位置编码**。顺序由**状态**（WM / STDP 迹 / LTM 印迹）承载 | 铁律① |
| **深度** | N 层堆叠，逐层精炼 | **无堆叠层**。深度 = 状态演化的时间轴 | 铁律① |
| **计算粒度** | 可批处理（序列维并行） | **逐 token 状态演化** → 无 batch 维、不能批处理 | 铁律③ |
| **稀疏发生在哪** | 稠密注意力 +（MoE 的）**专家路由**稀疏 | **突触存在性**稀疏：事件驱动的局部触碰 | 都稀疏，维度不同 |

### 2.4 推论（诚实）

1. **PHD-Net 拿不到 Transformer 的并行红利**。逐 token 串行 + 每步可并行工作量小，直接导致
   大机器吃不满——论证见《并行与加速架构分析》，本文不复述。
   ⚠ **P113 的实测把这条结论的形状改了一处**：其中「`M2_infer` 跑单核」那条
   **配置性**原因已被 `plain` 消除（5.41×），**剩下的全是架构性的**。
   但结论本身**不变**（§6.3）。
2. **PHD-Net 也不该拿 Transformer 的评价标准**。在 MMLU 一类知识/推理 benchmark 上比较一个
   无注意力、无位置编码、逐 token 的**词级联想续写器**是不公平比较。公平维度是：
   **单步触碰量、在线学习能力、状态容量、无灾难性遗忘**。
3. **注意力与 PHD-Net 对应物的关系是"功能替代"而非"同类"**。自注意力是
   *内容寻址的全局加权求和*——查询与键的内容相似度决定权重，需要全部位置参与计算；
   PHD-Net 的大空间表是*内容寻址的稀疏联想存储*——只有**已生长**的突触参与，
   计算量正比于活跃神经元数而与总容量无关（`train/config_1b.py:12`）。
   两者都做"按内容取回相关历史"，但**一个是全连接加权，一个是稀疏索引查找**。

## 三、与 MoE 的关系：只有"稀疏"相似

MoE 的稀疏是**学出来的路由**，PHD-Net 的稀疏是**长在结构上的先验**。这个差别决定了两者的
能力上界，比"谁更省算力"重要得多。

| 维度 | MoE（Shazeer et al. 2017, arXiv:1701.06538） | PHD-Net |
|---|---|---|
| **稀疏位置** | 每 token 激活 top-k **专家**（神经元块） | 每 token 激活 k 个**编码单元**（M1）/触碰**存在**的突触（M2/M3/M6） |
| **路由是否学习** | **是**。gating 网络 `g(x)` 的参数随主损失一起训练 | **否**。`_random_csr` 在建图时随机采样并固定（`sparse_pc.py:148`、`readout.py:808`） |
| **稀疏度由谁定** | 学习 + 容量因子/负载均衡损失共同决定 | 结构性先验：`k_sparse = w//8`、`conn_k = w//8`、`m_lateral = 16` |
| **训练信号** | 全局损失反传（需梯度） | 局部感知器 `p − t` + STDP 三因子（无梯度） |
| **专家容量不均** | 靠 auxiliary loss 矫正 | **天然存在但未处理**：见 §六幂律欠账 |

**1b 档实测稀疏口径**（`build_cfg("1b")` 实算，非估算）：

| 机制 | 口径 | 值 | 占比 |
|---|---|---|---|
| M1 k-WTA 输出 | `k_sparse = 128 / width = 1024` | **12.5%** | 激活稀疏 |
| M2 CSR 连接 | `conn_k = 128 / 1024` | **12.5%** | 连接稀疏 |
| M3 STDP 出边 | `m_lateral = 16 / n_top = 1024` | **1.56%** | 连接稀疏 |
| **M6 读出（生产 CLI）** | `conn_k = 128 / hidden = 3072` | **4.2%** | 连接稀疏 |

> M6 口径说明：`train/train.py:296` 的 `--readout-conn-k` **默认 128**（P108 / fhz 2026-10-01），
> 而**库默认 `config.readout_conn_k = 0`（稠密）**（`config.py:194`）。两者不一致是事实；
> `config_1b.py:81` 透传显式参数，`0` 时才是稠密主路径。本文按**生产 CLI 默认**记4.2%。

**诚实说明结构先验的代价**：结构先验 = **免训练路由**（不需要额外训练预算、不需要负载均衡
损失、不存在专家坍缩风险），但**失去自适应能力**——路由**不会**因为某个专家对当前任务更重要
而调整。当分布偏移时（换一个语种、换一个任务），均匀 k-conn 的分配不会自适应，
而 MoE 的 gating 网络**会**。这是 PHD-Net 在"结构稳定性"与"分布适应性"之间的取舍，
**不是缺陷，也不是免费收益**。

## 四、与大脑的对照（每条带出处，含争议标注）

### 4.1 神经元与突触数量级

| 口径 | 数值 | 来源 | 性质 |
|---|---|---|---|
| 人脑神经元总数 | **86.1 ± 8.1 × 10⁹**（另有 84.6 ± 9.8 × 10⁹ 非神经元） | Herculano-Houzel 2009, *PNAS* 106(13):5193–5198, DOI 10.1073/pnas.1201895109 | 同行评议，但**有争议**（见下） |
| 其中皮层神经元 | **16.34 ± 2.17 × 10⁹**（占 ~19%）；小脑 69.03 ± 6.65 × 10⁹（占 ~80.2%） |同上，经Friemborn et al. 2019 / Azevedo et al. 2009 区域分解 | 分区口径差异大 |
| 全脑突触总数 | **(2.42 ± 0.29) × 10¹⁴** | Herculano-Houzel et al. 2010, *Front. Neurosci.* 4:126, DOI 10.3389/fnins.2010.00126 | 单一方法的估测 |
| 新皮层突触总数 | **164 × 10¹²**（CV = 0.17） | Jacobson et al. 2018, *J. Comp. Neurol.* 532(9):e25669；同组亦报道 ≈125 万亿 | 立体学抽样，**变异系数 17%** |
| 全脑整合突触密度 | ~672,542 /mm²（人） | Bhatt et al. 2024, *J. Comp. Neurol.* 532(9):e25669 | 跨物种对比表 |

> ⚠ **争议必须标注**：Herculano-Houzel 的 86.1 ± 8.1 × 10⁹ 建立在 **NeuN 标记 + 各向同性
> fractionator** 上，而 NeuN 并非所有神经元类型普遍表达、其水平随成熟上升。
> Morse 2025, *Brain*（PMC11884752, DOI 10.1093/brain/awae390）明确质疑该数字的普适性：
>「现有估计无法被恰当地论证」。**所以本文不把 86.1 × 10⁹ 当定论**，只当作
> **"10¹⁰–10¹¹ 量级"** 这一数量级判断的依据。同理，突触数的 1.25×10¹⁴ / 1.64×10¹⁴ /
> 2.42×10¹⁴ 三个值来自**不同方法、不同脑区口径**，不可混用。

**与 PHD-Net 的量级差**：1b 档总突触容量 **1,217,249,536 ≈ 1.22 × 10⁹**
（`train/config_1b.py::capacity_report`，V=51,962，`readout_conn_k=128`），
相对全脑 (2.42 × 10¹⁴) 差**约 5 个数量级**；相对新皮层 1.64 × 10¹⁴ 同样差约 5 个数量级。
**这个差距不能靠"扩容量"抹平**，只能靠"每个突触承载多少可塑能力"缩小——见§五、§六。

### 4.2 稀疏度：文献有多种口径，无定论

⚠ **这是本文档最需要诚实标注的一处。**「大脑有多稀疏」**没有单一答案**，
不同测量方法给出的数字差异巨大：

| 口径 | 数值 | 方法 | 来源 |
|---|---|---|---|
| 能量受限推断 |并发活跃可能 **< 1%** 神经元 | 由皮层能量消耗反推可持续放电率 | Lennie 2003, *NatRev Neurosci* 4:317–327（"The Cost of Cortical Computation"；结论"possibly to fewer than 1%"） |
| 稀疏编码假说 | 约 **1–5%** 激活率 | 稀疏分布式表示的效率论证 | Olshausen & Field 1997, *Nature* 381:607–609, DOI 10.1038/381607a0 |
| 连接密度（推算） | ~7×10⁻⁸ 突触/nm³ 量级；人均突触数**跨越 3 个数量级**（1千–10万），几何均值 ~10⁴ | 解剖学计数 | 与 4.1 表 2 的密度值一致（Bhatt 2024）；每神经元突触数的**巨大分散度**见其 Table 1 |
| 冗余编码 | 数万神经元即可编码 95% 的信息 | 相关噪声的信息极限 | Francon et al. 2021, *Nat Commun* 12:5813, DOI 10.1038/s41467-020-20722-y |

**结论（必须这样写）**：把「大脑稀疏度 = 1–5%」当定论是**过度简化**。
它是一个**编码效率假说的量级**，不是测量共识；而**连接密度**与**激活稀疏度**是两个
不同量纲，混用会得出错误倍数。PHD-Net 目前的 12.5% / 4.2% / 1.56% 只应与
"**激活**稀疏度"这一口径比较。

### 4.3 逐机制同构对照

下表只列**机制 ↔ 神经认知对象**的对应关系，不评价实现好坏（实现见《架构设计》§2）。

| 机制 | 神经认知对应 | 出处 | 1b 档实际口径 | 库默认 |
|---|---|---|---|---|
| **M1** 稀疏分布式编码（k-WTA） | 皮层稀疏编码 + 侧抑制竞争 | Olshausen & Field 1997, *Nature* 381:607–609 | `k_sparse=128 / n_sdr=1024` → **12.5%** 输出稀疏（`sparse_encoder.py:126` `np.argpartition`） | 开 |
| M1 可学习稀疏词典 | 初级皮层 simple cell 感受野的经验学习 | Rao & Ballard 1999, *Nat Neurosci* 2:79–87, DOI 10.1038/4580 | Oja + 行范数双约束（1b 档 `eta_oja=0` **冻结**） | **关** |
| **M2** 预测编码主干 | 皮层预测编码：高层生成低层、误差回传精炼 | Rao & Ballard 1999（同上）；综述 Jiang & Rao 2022, arXiv:2112.10048 | 4 层 CSR 栈（`n_sdr→n_mid→n_top→n_mid→n_sdr`），`conn_k=128` → **12.5%** 连接率；1b 档 `eta_pc=0` **只前向不学习** | 开 |
| M2 结构性稀疏连接（CSR） | 皮层组织原则：dense representation + **sparse connectivity** | Binz et al. 2015, *Nat Neurosci* 18:256–261（"How many synapses per neuron are needed to model the nervous system?"，arXiv:1308.1749）——同量级稀疏 CSR 前馈连接 | `_random_csr` 发育期随机 + 固定 | 开 |
| **M3** STDP 时侧向关联 | 突触可塑性的时序因果律（前摄/后摄不对称） | Markram et al. 1997, *Trends Neurosci* 20(3):142–151；Bi & Poo 1998, *J Neurosci* 18(1):253–258 | `m_lateral=16` → **1.56%** 出边；**只走 numba CPU**（`model.py:49-57`） | 开 |
| M3 稳态缩放 / BCM / 逐突触自适应 LR | 突触稳态（Turrigiano et al. 1998, *Science* 282:273–275）、BCM 滑动阈值、局部二阶矩归一 | 同上 | 三开关分立；**自适应 LR 与 torch 后端不兼容** | 全部**关** |
| **M4a** 工作记忆 | PFC 漏整合（leaky integrate-and-fire）+ 有限槽位 + 基底核门控 | Miller & Cohen 2001, *Annu Rev Neurosci* 24:167–193（"An integrative theory of prefrontal cortex function"） | `n_slots` 有限槽 + `gamma_wm=0.85` 衰减 + 门控写入 | 开 |
| M4a 摘要槽 / 内容寻址写入 | PFC 的压缩/摘要与内容寻址聚合 | 同上 | `wm_summary_every=0`（关）、`wm_content_address=False` | **关** |
| **M4b** 大容量事件驱动稀疏表 | 稀疏长时记忆：容量靠**生长**（"fire together, wire together"）而非稠密预分配 | 突触发生与修剪；另 Kanerva 1988, *Spatial Memory Representation*（SDM）—— 源码 `sparse_alloc.py:9-13` 自引 | 1b 档 2²⁴×**72** = **1,207,959,552** 突触容量（**99.24%** of总容量） | 开 |
| M4b 分期睡眠 SWS/REM + downscaling | 睡眠驱动的突触巩固与稳态缩放 | Tononi & Cirelli 2014, *Science* 349(6254):94–98, DOI 10.1126/science.1254449 | `sleep_downscale=0.9` | **关** |
| **M5** 神经调制 | NE 新颖性 / ACh 编码-检索模式切换 / DA 巩固 | Hasselmo & Wyble 1997, *Nat Rev Neurosci* 3:715–725（编码/检索切换） | 库默认单标量（意外度 → Welford z → `σ(a·z)` 门）；四通道版 `multi_modulation` | 单标量开 / 四通道**关** |
| E/I 突触类型 + 发育临界期修剪 | 皮层 ~80% 兴奋 / 20% 抑制；可塑性窗口关闭 + 突触消除 | Song, Sjöström, Reigl, Nelson & Chklovskii 2005, *PLoS Biol* 3(11):e369（源码 `inits.py:6-9` 自引）；E/I 比见同文献 | `exc_ratio=0.8`、`crit_rate`、`prune_threshold=0.01` | 全部**关** |
| **M6** 读出（稀疏感知器 + softmax） | 群体编码输出：下游群体读出分布式表征 | Rumelhart & Zipser 1985（感知器学习）；softmax 读出见 PHD-Net 自有设计 | 生产 CLI **4.2% 均匀 k-conn**（`readout_conn_k=128`）；稠密等价 51,962×3,072 = **159,627,264** | 库默认稠密 / CLI 稀疏 |

**读法**：M1、M2、M3、M4a、M4b、M5(单标量)、M6 是**默认开启且已进入生产路径**的机制；
`learnable_encoder`、M3 三开关、M4a 两开关、M4b 睡眠、E/I + 临界期、M5 四通道
是**默认关闭**的机制（铁律④：行为变更以 config 开关承载且默认关闭），
它们在 `tests/checks_core.py::t_brain_homologues` 里与主路径一起做零崩溃自检，
但**没有生产实测结论**。

## 五、规模外推：方法与不确定性

**明确声明：PHD-Net 没有实测 PPL-规模曲线。** 本节给**方法**与**瓶颈分析**，
**不给**"预计能达到 X params / Y PPL"式承诺。

### 5.1 四档预设与容量实算

`train/config_1b.py:45-58` 定义四档。`capacity_report` 实算结果
（我方重跑核验，`V = 51,962`，`readout_conn_k=128`）：

| 项 | `smoke` | `1b` | `1b_max` | `30b` |
|---|---|---|---|---|
| width（`n_sdr`=`n_mid`=`n_top`） | 256 | **1024** | 4096 | 1024 |
| `k_sparse` / `conn_k` | 32 / 32 | **128 / 128** | 512 / 512 | 128 / 128 |
| `big_ltm_N` × `big_ltm_m` | 2²⁰×60 | **2²⁴×72** | 2²⁴×60 | **2²⁹×56** |
| M1 编码器 | 131,328 | 2,098,176 | 33,558,528 | 2,098,176 |
| M2 主干 CSR | 32,768 | 524,288 | 8,388,608 | 524,288 |
| M3 STDP | 4,096 | 16,384 | 65,536 | 16,384 |
| M6 读出（稀疏 k=128） | 6,651,136 | 6,651,136 | 6,651,136 | 6,651,136 |
| **固定突触小计** | 6,819,328 | **9,289,984** | 48,663,808 | 9,289,984 |
| **M4b 容量** | 62,914,560 | **1,207,959,552** | 1,006,632,960 | 30,064,771,072 |
| **总容量** | 69,733,888 | **1,217,249,536** | 1,055,296,768 | 30,074,061,056 |

> ⚠ **口径差异说明（1.370e9 / 1.217e9 为什么都对）**：
> 上表按**生产 CLI 默认 `readout_conn_k=128`** 计算，总容量 **1,217,249,536 ≈ 1.217e9**。
> 若按**稠密读出**（`readout_conn_k=0`，库默认）重算，同一 `big_ltm` 配置下
> 读出 = 51,962×3,072 = 159,627,264，总容量 = **1,370,225,664 ≈ 1.370e9**，
> M4b 占比降到 88.158%。
> **两个数字的差 = 159,627,264 − 6,651,136 = 152,976,128，即读出稠密/稀疏的差值。**
> 二者**都不是"不同词表"**，而是**同一词表下读出稀疏度不同**；引用时必须带
> `readout_conn_k` 口径。更早文档的 **1.317e9** 则是 `big_ltm_m=60` 时代
> （2²⁴×60 = 1,006,632,960）的值，**已作废**，不可与上述任一值混用。

### 5.2 哪些量线性增长、哪些会变成瓶颈

外推到更大档位时，三类部件的行为**完全不同**：

| 部件 | 增长行为 | 瓶颈性质 | 依据 |
|---|---|---|---|
| **M4b 大空间表** | 容量 **线性**增长（2²⁴→2²⁹ = 32×）；每步计算量**只正比于活跃神经元数**，与总容量无关 | **随机访问 → 访存受限**。索引映射本身就要 17.2 GB（`capacity_report` 的 `bigltm_neuron_map_MB`）。稀疏存储落得住的前提是 `csr_online`（`train.py:285-292`：dict ~100 B/条 → 在线 CSR ~16 B/条，实测 5.74×） | `config_1b.py:12`、`config_1b.py:119` |
| **M6 读出** | GEMV：矩阵规模 `V × hidden` 线性增长，**每步只传一个 `h` 向量** | **带宽受限**。这是唯一已上加速器的部件（`accel:npu`），但 4.2% 连接率只是把访存从 320 MB 降到 39 MB（8×），**不改变带宽受限的本质** | `backends/README.md` §二、`config.py` 稀疏读出口径 |
| **M2 CSR 主干** | 计算量线性增长。**P113 起默认走 `plain`**（`_csr_matvec`，带行级 `prange`）；`serial`（单核融合核）是历史默认，`fused` 已被否 | **并行度受限 → 已缓解**。P113 实测 `M2_infer` **6.92 → 1.28 ms/tok（5.41×）**。⚠ 但**进程用核数仍是 1.1 / 191** —— 这条现在归入§6.3 的架构性代价，不再是「配置没做对」 | 性能文档 §2.1/§4.2 |
| **M3 STDP** | `m_lateral` 固定 → **不随width 增长** | 不是瓶颈（实测 0.34%），但 **只走 numba CPU，无法上加速器**（`model.py:49-57`：迁移会丢自适应 LR / 稳态 / BCM / E-I 状态） | `model.py:49-57` |
| **M4b 在线 CSR 生长** | — | **无法上加速器**：`OnlineCSRTable` 的定长行 + 预留槽 + 生长是 CPU 结构操作 | `backends/README.md` §二 |

**外推方法**（三步，缺一不可比）：

1. **口径绑定**。PPL 锚点只有一组有效：**4K 段 394.4687 / 全语料 359.2603**
   （256 维栈、`eta_readout=0.15`，2026-09-28 换中文维基语料后重测）。
   更早的 78.16 / 90.2480 / 73.1166 属**旧语料口径**，只存于 git 历史，**不可混用**。
   ⚠ 读出改 fp32 后 PPL 与这些锚点**不可直接比**（语义更正确但口径不同），需重测。
2. **同 fraction、同机器、同数据才可比**。远程语料是分片级前缀抽样
   （`--remote-fraction` 默认 0.3），改 fraction 等于换数据分布。跨 run 比 PPL 前必须先对齐
   `data / remote / remote_fraction / lang / 分片数`。
3. **线性外推只在"瓶颈未转移"时成立**。上表显示 1b→30b 时M4b 容量 ×32 但
   **M2/M3/M4b 都在 CPU 上**，所以端到端步时不会随容量线性下降——
   `train/config_1b.py:54-56` 自己写明"1B 档 ~20 ms/tok → 30B 档**预计**数百 ms/tok"
   并标注"单机 1M tokens 不现实"。**这是源码里的假设，不是实测。**

### 5.3 外推的不确定性（必须一起写）

- **没有跨档位 PPL 曲线**。1b / 1b_max / 30b 三档**没有可比的 PPL 实测**，
  因此"容量 → 能力"的关系**尚未建立**。任何"30B 档能达到 X"的表述都是编造。
- **已知的历史事实是反方向的**：在**固定数据预算**下放大参数，PPL 反而变差
  （典型欠训练效应）。这说明"容量 → 能力"不是自动的。
  Transformer 侧的缩放律（Kaplan et al. 2020, arXiv:2001.08361；
  Hoffmann et al. 2022, arXiv:2203.15556）之所以能成立，前提是**参数量、数据量、
  计算量三者同步增长**；PHD-Net 目前**只具备第一项**。
- **稀疏度不随规模变化**。`k_sparse = w//8`、`conn_k = w//8` 使**连接率恒定 12.5%**，
  所以放大 width 只线性放大**固定突触**部分；而占99.24% 的 M4b 容量放大 32× 时，
  **稀疏度完全不变**。这意味着"更大"和"更稀疏"在当前设计里**不是同一件事**。
- **每突触效率未知**。脑同构的真正可比量不是突触总数，而是
  **"每个突触承载多少可塑能力"**。PHD-Net 的 M4b 容量是**随机生长**的，
  **利用率随训练增长**（`config_1b.py:21-22`：训练初期利用率低），
  而这个利用率的**实测曲线尚不存在**。

## 六、欠账与诚实边界

**这一节是本文档的价值所在。** 前五节给出结构优势，本节列出**尚未兑现的部分**。

### 6.1 读出已稀疏化，但**仍是均匀k-conn**，幂律分配器已实现但未接线

这是当前**唯一的架构级欠账**，且必须精确表述：

- ✅ **已做**：M6 读出在生产 CLI 下默认 `readout_conn_k=128` → **4.2% 连接率**
  （`train/train.py:296`），加速器已实现稀疏 gather-GEMV（P111）。
-❌ **未做**：稀疏读出**只支持均匀 k**。`Readout.__init__` 走 `_random_csr(rng, n_out, n_in, k, ...)`
  （`readout.py:806-809`），每行**恰好** k 条入边。
  后果是高频词（如"的"）与长尾词获得**同等容量**——**长尾词被过分配、高频词被欠分配**。
- ❌ **幂律分配器已实现但未接入**：`phdnet/sparse_alloc.py` 实现了
  `assign_conn_counts`（`k_i ∝ counts_i^alpha`，受 `k_min`/`k_max` 夹紧）与
  `build_powlaw_csr`（行宽不等，`indptr` 用 cumsum）。但：
  - `phdnet/readout.py` **不 import `sparse_alloc`**（`grep -n "sparse_alloc\|assign_conn_counts" phdnet/readout.py` 无命中）；
  - 模块自己的 docstring 写明：「本模块是**纯分配函数**：不参与前向/反向，**也未接入 `readout.py`**」；
  - `tests/verifiers/verify_readout_sparse_gate.py:37` 的 G4 幂律分组门禁处于
    `[SKIP] sparse_alloc 不可 import` 状态；`tools/bench_readout_sparse.py:113` 注释仍写
    「预留接口；`sparse_alloc.py` 由另一位同事并行实现中」——**注释已过期**。
- ⚠ **接线的前置阻塞**：加速器对**非均匀行宽 fail-fast**
  （`phdnet/backends/accel_readout.py:148-153`：`稀疏读出只支持均匀 k`），
  因为非均匀需要变长 CSR + segment sum，语义与实现都不同。
  **即使接上幂律分配器，也必须先解决加速器的非均匀 CSR 支持。**
-⚠ **分配器自身的已知局限**（源码自陈）：`alpha=1` 在 Zipf(1.0) 强偏斜词频上
  **极易撞 `k_min` 下限**导致秩相关下降，实践中 `alpha ∈ [0, 0.5]` 更合适；
  高频行同时可能撞 `k_max`。这是**预算的真实约束**，不是 bug。

### 6.2 无梯度 → 训练效率差距是结构性的

PHD-Net **不存在**任何反向传播路径（§二.2）。与Transformer 的差距因此**不由参数量、
学习率或优化器决定**，而由"是否可微"这一前提决定。
**这意味着"训练效率追赶 Transformer"不是一个可执行的工程目标**，
除非放弃铁律②（纯感知器 + STDP 的学习规则）——而那会取消整个脑同构框架。

### 6.3 191 核用不满（0.6%）是逐 token 语义的必然代价

实测遥测（1b 档，昇腾 191 核 + NPU）：**进程仅用 1.1 / 191 核（0.6%）而 NPU 99%**。

⚠ **P113 更新（这条结论保留，但其中一条原因已被排除）**：

此前「191 核用不满」里有**两条**并列原因：

| 原因 | 性质 | P113 后的状态 |
|---|---|---|
| 每步只推进一个 token，可并行工作量小（§二.1） | **架构性** | ✅ **保留** —— 不动 |
| `M2_infer` 跑在单核（`--m2-kernel serial`） | **配置性** | ❌ **已排除** —— P113 改用 `plain`（行级 `prange`），实测 **6.92 → 1.28 ms/tok（5.41×）** |

⚠ **但「M2 不再单核」不等于「核用满了」**：进程用核数仍是 **1.1 / 191**。
原因是 CPU 侧整体只剩 4.26 ms，且线程上限之上就是访存饱和区——
**并行度用上了，但 CPU 侧总量本来就小**，抬不高核占用率。

> **所以结论不变、而且更硬了**：
> **唯一可配置的那份原因已经被证明可以消除（P113 消除成功），
> 而剩下的 0.6% 完全是逐 token 语义的代价。**
> 「191 核用不满」不再是「还有优化没做」，而是**架构性用不满**。
> 论证见《并行与加速架构分析》§2.2，本文不复述。

### 6.4 精度语义代价：速度 vs 学习规则正确性

读出默认 **fp32**（P110）**不是为了访存，是因为低精度会破坏学习规则语义**。
实测非目标行更新保留率（`tools/probe_readout_precision.py`，判据=同精度舍入后元素是否真变了）：

| 精度 | 非目标行保留率 | 目标行保留率 | 语义后果 |
|---|---|---|---|
| **fp32** | **99.95%** | 100% | 精确`p − t`，现行默认 |
| fp16 | 26.67% | 100% | 73% 的非目标行更新被丢弃 |
| bf16 | 5.79% | 100% | 94% 被丢弃 |

**这不是免费收益，是实测取舍**：感知器规则的关键在于 `p − t` 里**只有目标行应被更新**
（`p[target] < 1` 使非目标行`dp = p > 0`，需靠"小增量被舍入吸收"来实现这种抑制）。
低精度下增量`|dp| ~ 1e-6` 落在半 ULP 附近（`|W| ~ 1e-2`）→ 大部分非目标行更新被舍入丢弃 →
**"只提升目标行"退化为纯 Hebbian 式的全行抬升**，学习规则被改变而非仅降精度。
⚠ 曾有"fp16 半 ULP 只有 bf16 的 1/8，能保住更新"的估算，被 P110 实测**推翻**。

### 6.5 中文能力未经检验

远程分片实测 `lang` 分布（`datasets/README.md` §六）：**en 50% / unk 47%（实为代码，CJK 0%）/ zh 仅 2%**。
只有末片是中文 L3 采样（中文 99.7%）。后果：`--data-lang zh` 过滤后只剩约 2% 的行，
且 `--remote-fraction 0.3` 取的前缀分片里几乎没有中文。
**这与早期文档记录的"中文 95%"直接矛盾**——属**数据问题**（制备/上传环节），非训练代码问题，
核对结论尚未产出。**因此 PHD-Net 的中文能力完全未经检验**，
而评测基线恰好是中文维基语料（PPL 锚点 394.4687 / 359.2603 口径）——
**评测口径与训练语料不匹配，这是一个尚未被承认的严重问题。**

### 6.6 其余开放项

| 项| 性质 | 状态 |
|---|---|---|
| **1b 档表征冻结**（`eta_pc = eta_oja = 0`） | 实测取舍 | 多轮实测最优解（`config_1b.py:77`），但意味着**主干几乎不再学新表征**，可塑性只落在 M3/M6 |
| **多数机制默认关闭** | 工程现实 | 见§四——默认关闭的机制只有零崩溃自检，**没有生产实测结论** |
| **无跨档位 PPL 曲线** | 方法论缺口 | §五.3——任何规模结论都只能写成假设 |
| **缺可比benchmark** | 评价缺口 | 与前沿模型**无法**在同一张能力表上比较；本文因此不做能力排名 |
| **M3 STDP 只走 numba CPU** | 平台硬约束 | 迁移到 torch 会丢自适应 LR / 稳态 / BCM / E-I 状态（`model.py:49-57`） |
| **M4b 在线 CSR 生长无法上加速器** | 平台硬约束 | 定长行 + 预留槽 + 生长是 CPU 结构操作（`backends/README.md` §二） |
| **加速器对非均匀 CSR fail-fast** | 阻塞 §6.1 | `accel_readout.py:148-153` |
| GitHub 侧 CI 仍红 | 工程债 | 两套 CI（`.gitcode/`、`.github/`），**无 Jenkinsfile** |

### 6.7 不做的事

本文**不**给"预计 N 年追上 X"式预测；**不**给无平台的加速倍数（x86 与昇腾常常方向相反）；
**不**引用旧 PPL 锚点；**不**把「大脑稀疏度 = 1–5%」或「人脑 86.1 × 10⁹ 神经元」
当无争议定论使用；**不**声称 PHD-Net 在任何能力维度上与 Transformer 可比。
