Overview

它是什么

PHD-Net 是一个用 NumPy/Numba 实现、可跑到 PyTorch / 昇腾 NPU 上的类脑语言模型架构：预测编码提供表示，Hebbian/STDP 提供局部学习，工作记忆 + 大容量印迹表提供长程依赖。唯一的注意力机制是不存在的——长程依赖由记忆机制承担，而不是架构 shortcuts。

无自注意力

禁自注意力 / 位置编码 / 堆叠层。长程依赖交给 M4a/M4b 记忆机制。

局部学习

Hebbian / STDP 全部局部化，没有反向传播，也没有全局损失对权重的梯度。

事件驱动

只触碰活跃通路；每步计算量只正比于活跃神经元数，与 1B 总容量解耦。

逐 token 语义

一次前向 = 一个 token，状态跨 token / 分片 / epoch 连续演化，W 每步原地更新。

Four Iron Laws

四条铁律

这不是风格偏好，是写进仓库的架构约束。任何新部件都要先过这四关。

LAW 01

禁自注意力 / 位置编码 / 堆叠层

长程依赖由记忆机制承担，不由架构 shortcuts 承担。人脑没有全局 softmax，也不需要它。

LAW 02

每个机制必须有神经认知对应

不接受「工程上好用但无认知对应」的部件。六机制各有一条脑科学依据（见下表）。

LAW 03

逐 token 语义，不允许批处理

状态跨 token / 跨分片 / 跨 epoch 连续演化，读出 W 每步原地更新。这是语义约束，不是性能取舍。

LAW 04

行为变更走 config 开关，默认关闭

新增行为一律以 config 开关承载且默认关闭；例外仅两个：csr_online / k_sparse 默认开启。

Six Mechanisms

六机制速览

每个机制都对应一类神经认知现象，并落到具体文件。稀疏性是架构原则，不只是优化：人脑长程连接率约 2e-8、平均每神经元约 1744 条突触；本项目 M2 = 12.5%、M3 = 1.56%、M4b = 事件驱动、M1 输出 k-WTA 12.5%。

M1稀疏编码器

皮层稀疏发放 + 侧抑制 WTA

把组合输入编码成稀疏分布式表示（SDR），每步只点亮约 1/8 的神经元，侧抑制完成竞争。另有无词典分词的 M7 词涌现，给出词级 SDR。

实现 phdnet/sparse_encoder.py稀疏性 k-WTA，输出 12.5% 活跃

M2预测编码主干

dense representation + sparse connectivity

不堆层、不自注意力。每层基于当前表示预测下一表示，预测误差驱动更新；连接以 CSR 结构性稀疏存储，不存在的突触不存储、不计算。

实现 phdnet/sparse_pc.py（SparsePCStack）稀疏性 12.5% 连接率，4 层

M3STDP 时序预测

稀疏拓扑突触迹

局部学习规则：发放时间序决定突触增强 / 抑制，突触迹沿活跃通路累积，是 "fire together, wire together" 的算术形式。无反向传播。

实现 phdnet/plasticity.py + stdp_kernels.py稀疏性 1.56% 连接率，m_lateral=16

长程印迹 · 事件驱动稀疏表

224 神经元 × 72 出边上限的事件驱动印迹表，随经验生长而非构建即存在。每步计算量只正比于活跃神经元数。

M5神经调制

surprise z 分数门控 / 四通道

用预测误差的 z 分数（意外程度）门控学习与写入：意外大时多学、符合预期时少动，四通道对应不同调质功能。

实现 phdnet/modulator.py稀疏性 —
稀疏化已落地，但仍是欠账：M6 读出已稀疏化——--readout-conn-k 默认 128（每输出单元 128 条入边 =4.2% 连接率，词表 73,958 × 4.2%），访存从稠密 fp32 的 866.7 MiB 降到 113.6 MB（8.0×，含列索引开销），且已在加速器上实现均匀 k 的 gather-GEMV（读出真正跑在 NPU 上）。但它仍是均匀 k-conn，不是幂律异质分配——幂律分配器（phdnet/sparse_alloc.py）已实现但未接入读出，加速器对非均匀行宽 fail-fast。与人脑 ~2e-8 连接率仍差约 6 个数量级。

Precision

精度口径

这个项目对精度的取舍理由几乎都与「学习」而非「省显存」有关，而且随硬件平台变化——x86 与昇腾的加速方向常常相反，不可混用。

读出：fp8（默认，P189）—— 位模式存储 + fp16 迭代

fhz 2026-10-07 决策「模型 fp8，迭代 fp16」：W 以 fp8 e4m3fn 位模式（uint8 承载）存储（1 B/元素，访存收益完整保留），迭代走 fp16 域 rank-1 更新后 RNE cast 回位模式。感知器 p − t 的非目标行更新量 ≈1e-6 会被粗步长舍入吞掉（学习部分退化为纯 Hebbian），这是知情取舍，验收靠 probe_PPL。实测非目标行更新保留率（tools/probe_readout_precision.py，|W|~1e-2 / |dp|~1e-6 档）：

fp32 99.95%（精确 p − t）｜fp16 26.67%｜bf16 5.79%；目标行全部 100%（目标更新 ~1e-2 ≫ 半 ULP）。fp8 步长比 fp16 粗约 4 倍 → 保留率更低。低精度不是免费的速度收益。
910B 无 fp8 matmul 算子（ERR01007）→ 前向可选每步 CPU 转换 int8 码本走 int8 算子（--fp8-conv 选 torch/nogil）。⚠ 原 rust 选项已随 phdnet_rs/ 整体删除（P188），传旧值会按 torch 处理（不报错，因为两条 Python 路径逐位一致）。int 族显式请求仍禁用（P163）；fp4/int4 仍禁用（P152）

编码器与分词

M1 编码器 --encoder-dtype 默认 fp32：x86 上 fp32 比 fp64 快 1.80×；昇腾 aarch64 上两者都不慢——平台自适应走自写 numba GEMV 核（_gemv_rows）绕开了 BLAS，故与 dtype 无关。⚠ x86 与昇腾的加速方向常常相反，不可混用。分词 onehot 缓冲 fp16：值只有 0/1 无损，1B 词表每步缓冲/传输 208 KB → 104 KB。

检查点 低精度存位模式（uint16/uint8），加载侧按 meta["ckpt_dtype"] 无损解码；词表快照自包含，无需外部词表

fp8 的硬件限制与软件绕行（P189）

实测昇腾 Ascend910B4 + CANN 8.5 + torch_npu 2.9 对 float8_e4m3fn/e5m2 的建张量 / cast / matmul 全部报错，torch.ops 零个 fp8 算子——910B4 没有 FP8 矩阵乘单元。P189 起不因此放弃 fp8 精度：位模式（uint8 承载）存储绕行，访存与原生 fp8 相同；换 910C/950 或 ROCm gfx942 时探测自动命中原生 fp8 路径。

Performance

性能区间（1B 档，昇腾 191 核 + NPU）

12.09 ms/tok

2026-10-01 实测（1b 档，昇腾 191 核 + NPU，52k token 稳态）。区间 20–110 ms/tok 是历史对照。ms/tok 必带平台与档位。

读出 7.83 ms/tok（64.7%）

不是带宽受限：稀疏臂每步触达 229.15 MiB，按 ~800 GB/s 算下界 0.300 ms → 实测是下界的 26.1×，瓶颈在算子效率而非访存。

191 核用不满

架构性 + 配置性各半：逐 token 语义禁止数据并行（架构性）；M2 曾跑单核 6.92 ms（配置性，已由 --m2-kernel plain 解决 → 1.28 ms，5.41×）。剩余 CPU 侧 4.26 ms 中只有 M1 可安全与读出重叠（M2 依赖 PC 权重、PC_learn 在读出之后）。

门禁与 CI：python tests/run_tests.py fast = 9/9（零回归门槛），专项 verifier 按 tests/verifiers/verify_*.py 实计（不含基准脚本 bench_accel_path.py）；verify_ms_stream 会对改动文件 py_compile 并真跑 train.py --help。CI 两套：.gitcode/workflows/ci.yml 与 .github/workflows/ci.yml（镜像）——仓库没有 Jenkinsfile。
评测基线：口径 256 维栈、eta_readout=0.15；现行锚点 4K 段 394.4687 / 全语料 359.2603（评测语料 2026-09-28 起换为中文维基条目合集，eval_corpus/internal_corpus.txt 实测 27,034 字符）。复测入口 py -3.14 tools/rebaseline.py --json（默认显式 fp32；--readout-dtype fp8 不判历史锚点一致）。P192 STDP 修正后实测质量变化见性能文档 §10.1，不覆盖历史锚点。旧口径 78.16 / 90.2480 / 73.1166 只存于 git 历史，不可混用。
已知开放项：M4b 复测归因 · fp16 下 PPL 是否下降 · 数据集语种（远程分片实测中文仅 2%、unk 47%，是代码问题，与旧记录矛盾）· 检查点 compact_csr 向量化后仍 3.9 s/10 万行 · M6 幂律稀疏化（架构欠账） · GitHub Actions 仍红。
Quick Start

跑起来

唯一生产训练入口是 train/train.py。全部开关、默认值与「为什么是这个值」见 train/README.md。

# 安装（numpy/numba/psutil/pyarrow 必装，torch 可选段）
# 注意：numpy 需 < 2.3（新版与 numba 不兼容），numba ≥ 0.61
pip install -r requirements.txt

# 最小可跑（冒烟，分钟级，只验管线）
python train/train.py --preset smoke --data sft --tokens 2000

# 门禁：fast 9/9 零回归
python tests/run_tests.py fast

# 标准 1B 档训练（本地 datasets/ 入口）
python train/train.py --preset 1b --data pretrain --tokens 1000000

# ModelScope 远程流式入口（HTTP Range，零本地落盘）
python train/train.py --preset 1b --data pretrain --remote-data

# 推理 / 对话
python train/infer.py --model outputs/models/phdnet1b_1b_pretrain_final.npz --chat
# 终端 TUI（ANSI 轻量界面，word 与 1B 双后端，可 --selftest）
python chat/tui.py

训练数据两入口：本地 datasets/（gitignore 的独立仓库，由 tools/ 转换脚本生成）；--remote-data 走 ModelScope HTTP Range 流式直读，零落盘。
