## ① 多卡互联（fhz 指示「训练代码请支持多卡互联」）
新增 `phdnet/backends/sharded_readout.py::ShardedAccelReadout`：
持 N 个 AccelReadout 分片（各持 V/N 词表行、各自设备/降级链/master），
主卡全局 softmax + dp 行分片下发 + 各分卡 rank-1。

**为什么是列并行而非 DDP**（P14 已论证，本次沿用）：逐 token 事件驱动
稀疏网络无 batch 维、无反向图、全局状态（WM/STDP/LTM）跨样本连续携带
→ 标准 DDP/DataParallel 在此没有可分的梯度或 batch 轴。

**接入面**：
- `phdnet/backends/accel_readout.py`：新增 `_accel_apply_dp`（分片 rank-1
  原语，覆盖稠密/int8/fp8-bits/master 四种存储）；`pick_readout_backend`
  在 `accel_readout_devices>1` 时分派到 ShardedAccelReadout
- `phdnet/config.py`：新字段 `accel_readout_devices: int = 1`
- `train/train.py`：新 CLI `--accel-devices N`
- **单卡路径零变更**：devices=1 时完全走原 AccelReadout

**诚实边界（写进 docstring 与门禁文件头）**：
- 仅**稠密读出**（`--readout-conn-k 0`）支持多卡；稀疏多卡 fail-fast 提示
- 等价判据是 **fp32 容差 1e-6**（实测 max|d|=1.49e-08），**不是逐位**——
  单卡 `W.add_(outer(dp,ht))` 一次写整张 W，多卡按行切片各写自己那片，
  torch.outer 的分片 kernel 分块不同。与 P14 gate_multi_device 的
  「同设备分片逐位」口径**不同**（那个是 cat 后整体更新），不得混淆
- 上游 M1-M5（CPU numba）、LTM/STDP/WM（全局事件状态）不并行
- 1B 档读出占端到端 ~20% → N 卡上限 1/(1-0.196+0.196/N)（N=4 → 1.15×）

**新门禁** `tests/gates/gate_multi_device_sharded.py` 14/14：
A 单卡零回归 / B 分片均衡+行覆盖+w0行对应+单设备fail-fast /
C 前向逐位+更新容差+nll一致 / D 稀疏fail-fast / E 工厂分派

## ② 默认值调整（fhz 2026-10-18 指示）
- `replay_every: 4 → 16`（phdnet/config.py）：实测服务器 1b 档
  M6_replay 5.6-6.2 → 1.2-1.4 ms/tok；本机端到端 11.00 → 8.27 ms/tok
  （−25%），final_ppl 13,975 → 14,225（1.8%，噪声内）。语义 = 巩固周期
  拉长 4×（非关闭）。`--replay-every 4` 可复原
- `--numba-threads: 8 → 16`：按 fhz 指示；help 里记录 P201 本机 x86
  实测的负收益区间（16/32 的 fork/join 屏障 24.7/64.3 µs/区）与
  「本机 ≠ 昇腾」纪律，服务器 A/B 判据写在 help 中

## ③ 训练时间预估公式（README §4）
主式 T(h) = tokens × ms_per_token / 3.6e6，ms/tok = B/(f_cpu·e_cpu) + S；
S 分解为 readout_overlap + replay_ms/replay_every + other，逐项给实测锚点；
附 1B 档三档配置的 ms/tok 与 1M/10M token 时长表；三条纪律
（不用首行 cum 口径 / ms/tok 必须目标机标定 / 词表×曝光只影响能否学会）
