perf(P166): make the 30b preset actually runnable by shrinking the reverse index

fhz asked for the 30b training code to match 1b except for parameters, and asked
for first and SFT data through the two ModelScope repositories.

The 30b preset already existed and build_cfg returns 30.295e9 capacity, with
only big_ltm_N and big_ltm_m differing from 1b across 129 of 131 fields, the same
readout width and the same n_h of 3072. But it could not run. The blocker is not a
parameter, it is SparseLTM._rev_to_csr, which builds a dense indptr of length
max(big_i)+1 while idx is hashed uniformly across n_neurons. That is 134 MB at 1b
and 4094 MB at 30b, and it is allocated unconditionally inside __init__, so the
machine pays four gigabytes before the first step. Meanwhile rev holds only
n_dim times k_hash keys, which is 4096 at 30b, or four ten-thousandths of one
percent of the dense domain, so the array is almost entirely empty intervals.

Three implementations now exist and all three were checked against each other.
The original dense kernel keeps working, selected when the dense array is under
32 MB, so small presets such as smoke are untouched. A binary-search version over
sparse keys was added first and is correct but slow, 93.7 microseconds at 30b for
1024 active entries. Then a hashing version with open addressing and linear
probing was tried, hashing by multiplication mix rather than masking because
project rules forbid plain masking on structured keys. The first hashing attempt
stored only the key in each slot and still had to binary-search for the interval
afterwards, which measured 0.9x, that is slower than plain binary search, since
the extra search was wasted. Storing the key and the position in two parallel
arrays removed that second search and made it 6.65x faster than binary search at
256 active entries and 4.96x at 1024, at 13.8 and 76.0 microseconds against 91.8
and 376.9. Memory goes from 4094 MB to 256 KB, a factor of 16375.

All three kernels agree bit for bit across two neuron counts, three activity
levels, deliberately repeated keys to exercise repeated accumulation, and
absent plus negative keys to confirm they are skipped exactly as dict.get would.
The new gate tests/verifiers/verify_rev_index.py locks that in along with the
switching threshold, the power-of-two table size, the load factor of at most a
quarter, slot uniqueness and index validity.

Gates: fast 9/9, rev_index, ltm_kernels, ltm_learn_batch, encoder_gemv,
precision_policy and accel_readout all PASS.
